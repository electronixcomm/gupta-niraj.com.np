Why MSI and LSI?

In Unit 4 the goal was to use the fewest gates. With integrated circuits that is no longer the right measure. Cost depends on the number and type of ICs and the number of interconnections, not the gate count.

ICs are grouped by how many gates they contain: SSI (small, a few independent gates), MSI (medium, a complete function such as an adder or decoder), LSI (large, e.g. ROM, PLA) and VLSI. MSI functions such as adders, comparators, decoders, encoders and multiplexers are standard building blocks, and they also appear inside larger LSI and VLSI chips.

Design procedure in this unit: where a block is designed from a word statement (decoder, encoder, MUX, DEMUX, comparator, BCD correction logic) we use the same six steps as Unit 4. Where an existing block is used to build a function (decoder + OR, MUX, ROM, PLA) we follow that block's own implementation procedure.
Syllabus 5.1

Binary parallel adder

A full adder (Unit 4) adds two bits and a carry. To add two n-bit numbers A and B there are two methods:

  • Serial addition: one full adder plus a storage element for the carry. Bit pairs pass through it one at a time, least significant first.
  • Parallel addition: n full adders, all bits applied at the same time. The carry-out of each full adder feeds the carry-in of the next one to its left.

A binary parallel adder is n full adders connected in a chain. Mano's example adds A = 1011 and B = 0011:

Subscript i4321
Input carry0110Cᵢ
Augend1011Aᵢ
Addend0011Bᵢ
Sum1110Sᵢ
Output carry0011Cᵢ₊₁
Why not use the six steps here? A 4-bit adder has 9 inputs (A₄–A₁, B₄–B₁, C₁), so its truth table would have 2⁹ = 512 rows. Cascading a known circuit (the full adder) gives a simple, regular design instead. This is typical of MSI design.

Carry propagation

The outputs of a parallel adder are only correct after the carry has rippled through every stage. S₄ cannot settle until C₄ settles, which waits for C₃, and so on back to C₁. In the full adder of Unit 4 the carry passes through an AND gate and an OR gate, i.e. 2 gate levels per stage, so an n-bit adder needs 2n gate levels for the carry. This carry propagation delay limits the speed of addition. It can be reduced with faster gates or with the look-ahead carry method (optional section below).

Optional · beyond syllabus

Binary adder-subtractor

A − B = A + (2's complement of B) = A + B′ + 1. One circuit can do both jobs: put an XOR gate on each B input and connect a mode input M to every XOR and to C₁.

  • M = 0: B ⊕ 0 = B and C₁ = 0, so the circuit adds A + B.
  • M = 1: B ⊕ 1 = B′ and C₁ = 1, so it computes A + B′ + 1 = A − B.

For unsigned numbers, C₅ = 1 means A ≥ B and the result is A − B. C₅ = 0 means A < B and the result is the 2's complement of B − A.

Optional · beyond syllabus

Look-ahead carry

Define for each stage the carry propagate Pᵢ and carry generate Gᵢ:

Pᵢ = Aᵢ ⊕ Bᵢ Gᵢ = AᵢBᵢ
Sᵢ = Pᵢ ⊕ Cᵢ Cᵢ₊₁ = Gᵢ + PᵢCᵢ

Substituting each carry into the next gives every carry directly in terms of P, G and C₁, as a two-level sum of products:

C₂ = G₁ + P₁C₁
C₃ = G₂ + P₂G₁ + P₂P₁C₁
C₄ = G₃ + P₃G₂ + P₃P₂G₁ + P₃P₂P₁C₁

All carries now appear after the same two gate levels once P and G are ready, so S₂ to S₄ have equal delay. The bench computes the carries both ways; they always match.

Syllabus 5.2

Decimal adder (BCD adder)

Calculators and some computers do arithmetic directly in decimal, with each digit in binary-coded form. A decimal adder adds two coded decimal digits plus a carry and gives a coded digit plus a carry. It needs at least 9 inputs (4 + 4 + carry-in) and 5 outputs (4 + carry-out). The circuit depends on the code; here we use BCD.

The classical method would need a 512-row table. Instead, add the two BCD digits with a 4-bit binary adder, then correct the result. Since each digit is at most 9, the sum is at most 9 + 9 + 1 = 19.

1
Step 1State the problem

The 4-bit binary adder gives the sum as 5 bits: its output carry K (weight 16) and four sum bits (weights 8, 4, 2, 1). Four bits alone only reach 15; with K the range is 0 to 31, of which only 0 to 19 can occur (e.g. 19 = K 1, sum bits 0011, i.e. 16 + 3). Design a circuit that detects when this binary sum is not a valid BCD result, so 0110 (6) can be added to correct it and an output carry produced.

Check your understanding · 5.2

Q1Add 8 + 7 in BCD and show the correction.Answer

1000 + 0111 = 1111 (binary 15), K = 0. Z₈Z₄ = 1, so C = 1. Add 0110: 1111 + 0110 = 1 0101; ignore the carry. Result: C = 1, sum 0101, i.e. BCD 1 0101 = 15 ✓.

Q2Add 9 + 9 + 1 (carry-in) in BCD.Answer

1001 + 1001 + 1 = 1 0011 (19): K = 1, so C = 1. 0011 + 0110 = 1001. Result C = 1, sum 1001 = 19 ✓.

Q3Why is 0110 the correction value?Answer

A 4-bit binary adder carries at 16, but a decimal digit should carry at 10. The difference is 16 − 10 = 6, so adding 6 skips the six unused codes 1010–1111 and produces the correct carry.

Q4How many unused input combinations does a BCD adder have?Mano 5-9

9 inputs give 2⁹ = 512 combinations. Valid ones: 10 × 10 digit pairs × 2 carry values = 200. Unused: 512 − 200 = 312.

Syllabus 5.3

Magnitude comparator

A magnitude comparator compares two numbers A and B and shows the result on three outputs: (A > B), (A = B) and (A < B). For two n-bit numbers the truth table has 2²ⁿ rows, which is already 256 rows for n = 4. So we design a small 2-bit comparator with the six steps, spot the pattern, and extend it to 4 bits with an algorithm.

Design · 2-bit magnitude comparator

1
Step 1State the problem

Compare two 2-bit unsigned numbers and indicate whether the first is greater than, equal to, or less than the second.

2
Step 2Determine the number of inputs and outputs

4 inputs (2 bits of each number), 3 outputs (one per relation; exactly one is 1).

3
Step 3Assign letter symbols
InputsOutputs
A = A₁A₀, B = B₁B₀G = (A > B), E = (A = B), L = (A < B)
4
Step 4Derive the truth table
5
Step 5Obtain the simplified Boolean functions

The 1s of E are isolated (00=00, 01=01, 10=10, 11=11), so the K-map cannot simplify E. Instead, give each bit position an equal-bit signal, the XNOR of its two bits:

xᵢ = AᵢBᵢ + Aᵢ′Bᵢ′ → xᵢ = 1 when Aᵢ and Bᵢ are the same (both 0 or both 1), xᵢ = 0 when they differ

With these signals the three functions take a regular form. E needs every position to match, so it ANDs all the xᵢ. G and L compare the left bits first, and look at the right bits only when the left bits are equal (x₁ = 1):

E = x₁x₀ (AND of the XNOR results of each bit position: 1 only when every bit of A equals the bit of B in the same position)
G = A₁B₁′ + x₁A₀B₀′ (= A₁B₁′ + A₀B₁′B₀′ + A₁A₀B₀′)
L = A₁′B₁ + x₁A₀′B₀ (= A₁′B₁ + A₁′A₀′B₀ + A₀′B₁B₀)

Where the bracketed forms come from. Since x₁ = A₁B₁ + A₁′B₁′ (XNOR of the MSBs), substitute it into the second term and simplify. The result is exactly the K-map answer above:

x₁A₀B₀′ = (A₁B₁ + A₁′B₁′)A₀B₀′ = A₁A₀B₁B₀′ + A₁′A₀B₁′B₀′ (substitute x₁)
G = A₁B₁′ + A₁A₀B₁B₀′ + A₁′A₀B₁′B₀′
= A₁(B₁′ + B₁A₀B₀′) + B₁′(A₁ + A₁′A₀B₀′) (use A₁B₁′ twice, since x + x = x, and pair it with each term)
= A₁(B₁′ + A₀B₀′) + B₁′(A₁ + A₀B₀′) (x′ + xy = x′ + y, and x + x′y = x + y)
= A₁B₁′ + A₁A₀B₀′ + A₀B₁′B₀′ ✓
x₁A₀′B₀ = (A₁B₁ + A₁′B₁′)A₀′B₀ = A₁A₀′B₁B₀ + A₁′A₀′B₁′B₀ (substitute x₁)
L = A₁′B₁ + A₁A₀′B₁B₀ + A₁′A₀′B₁′B₀
= B₁(A₁′ + A₁A₀′B₀) + A₁′(B₁ + B₁′A₀′B₀) (same steps, A and B swapped)
= A₁′B₁ + A₀′B₁B₀ + A₁′A₀′B₀ ✓

Both forms are correct. The x₁ form is preferred in circuits because the XNOR outputs x₁, x₀ are already needed for E, so G and L reuse them.

How to read G. For two 2-bit numbers A = A₁A₀ and B = B₁B₀, A is greater than B when:

  1. the MSB of A is 1 and the MSB of B is 0, giving the term A₁B₁′, OR
  2. the MSBs are equal (x₁ = 1), so we check the LSBs, and the LSB of A is 1 while the LSB of B is 0, giving the term x₁A₀B₀′.

Therefore G = A₁B₁′ + x₁A₀B₀′. By the same logic with A and B swapped, L = A₁′B₁ + x₁A₀′B₀.

Step 6Draw the logic diagram

Extending to 4 bits: the algorithm

Compare the bits the way a person compares numbers: start at the most significant position, and move right only while the bits are equal. The first unequal pair decides. With xᵢ = AᵢBᵢ + Aᵢ′Bᵢ′ for i = 0 to 3:

(A = B) = x₃x₂x₁x₀ (AND of the XNOR results of each bit position: 1 only when every bit of A equals the bit of B in the same position)
(A > B) = A₃B₃′ + x₃A₂B₂′ + x₃x₂A₁B₁′ + x₃x₂x₁A₀B₀′
(A < B) = A₃′B₃ + x₃A₂′B₂ + x₃x₂A₁′B₁ + x₃x₂x₁A₀′B₀

The four x signals are shared by all three outputs, which keeps the circuit (Mano Fig. 5-7) regular. The same circuit also compares two BCD digits.

The truth table grows as 2²ⁿ (256 rows for 4 bits, 65 536 for 8 bits), but the comparison follows a regular rule that repeats for every bit position. Writing that rule as Boolean equations gives the circuit directly.

Decoders and encoders

An n-bit binary code can represent up to 2ⁿ distinct elements. A decoder converts binary information from n input lines to at most 2ⁿ unique output lines. If some input combinations are unused, it has fewer outputs: an n-to-m-line decoder has m ≤ 2ⁿ. Each output generates one minterm of the inputs. An encoder does the reverse.

Combinational circuits from a decoder

A decoder produces all 2ⁿ minterms, and any Boolean function is a sum of minterms. So any combinational circuit with n inputs and m outputs can be built from an n-to-2ⁿ-line decoder and m OR gates.

  1. Express each output function as a sum of minterms (from the truth table).
  2. Choose a decoder with n inputs that generates all 2ⁿ minterms.
  3. For each output, connect the decoder outputs of its minterms to one OR gate.

Example (Mano 5-1): full adder with a decoder. From the full-adder truth table, S = Σ(1, 2, 4, 7) and C = Σ(3, 5, 6, 7). Use a 3-to-8 decoder and two 4-input OR gates.

If a function has more than 2ⁿ/2 minterms, its complement F′ has fewer. Then a NOR gate over the minterms of F′ gives F with fewer gate inputs. The decoder method suits circuits with many outputs, each having few minterms.

Decoder with an enable input

Most IC decoders have an enable input E. Mano Fig. 5-10 is a 2-to-4 decoder built from NAND gates, so its outputs are active-low (the selected output is 0) and it is enabled when E = 0. When E = 1 all outputs are 1, whatever A and B are.

The same circuit is also a demultiplexer: treat E as the data input and A, B as select lines. The value on E then appears on the output selected by AB, while the other outputs stay at 1. That is why it is called a decoder/demultiplexer (see 5.5 Demultiplexer).

Syllabus 5.5 · demultiplexer added to the course

Multiplexers and demultiplexers

A multiplexer (MUX, or data selector) selects binary information from one of many input lines and sends it to a single output. Which input is selected depends on the selection lines: normally 2ⁿ inputs and n selection lines. A demultiplexer does the opposite: one input, routed to one of 2ⁿ outputs.

Boolean function implementation with a multiplexer

A MUX is a decoder with the OR gate already built in. A 2ⁿ-to-1 MUX can implement any function of n + 1 variables:

  1. Write the function as a sum of minterms. Connect the last n variables to the selection lines (the second variable to the highest select line, and so on).
  2. The first variable, say A, is applied to the data inputs as A, A′, 1 or 0.
  3. Draw the implementation table: one column per data input. Top row: minterms with A′ (0 to 2ⁿ − 1). Bottom row: minterms with A (2ⁿ to 2ⁿ⁺¹ − 1). Circle the function's minterms.
  4. For each column: neither circled → 0; both circled → 1; bottom only → A; top only → A′.

Example (Mano Fig. 5-18): F(A, B, C) = Σ(1, 3, 5, 6) with a 4-to-1 MUX, B → s₁, C → s₀. The implementation table gives I₀ = 0, I₁ = 1, I₂ = A, I₃ = A′.

Decoder method vs MUX method. The decoder method needs one decoder and one OR gate per output. The MUX method needs one MUX per output. So circuits with few outputs suit multiplexers; circuits with many outputs suit decoders. In practice decoders are mostly used to decode binary information and multiplexers to select a path from many sources to one destination.

Read-only memory (ROM) and programmable logic array (PLA)

A programmable logic device (PLD) is an IC whose internal AND and OR gates are connected through electronic fuses. "Programming" means blowing the fuses on paths that must be broken, a hardware procedure. PLDs differ in where the fuses are:

DeviceAND arrayOR array
PROMFixed (a full decoder)Programmable
PLAProgrammableProgrammable
PAL (optional)ProgrammableFixed

Read-only memory

A ROM contains a decoder and OR gates in one IC, with programmable connections between them. It is used to implement complex combinational circuits or as permanent storage; the stored pattern stays when power is switched off.

A ROM has n input lines and m output lines. Each input combination is an address; each output bit pattern is a word of m bits. There are 2ⁿ addresses, so the ROM stores 2ⁿ words and is described as a 2ⁿ × m ROM.

Example: a 32 × 4 ROM has 5 inputs (2⁵ = 32). Inside, a 5 × 32 decoder (32 AND gates, 5 inverters) produces the 32 minterms. Each minterm connects through a fuse to each of the 4 OR gates, so there are 32 × 4 = 128 fuses. Blowing a fuse removes that minterm from that output.

Combinational logic implementation with a ROM

  1. From the number of inputs n and outputs m, choose a 2ⁿ × m ROM.
  2. Write the ROM truth table (program table). No simplification is needed.
  3. For each output, blow the fuses of the minterms where that output is 0; keep the fuses where it is 1.

Example (Mano Fig. 5-23): two inputs, two outputs, F₁ = Σ(1, 2, 3), F₂ = Σ(0, 2), so a 4 × 2 ROM with 8 fuses. The truth table has three 0s, so three fuses are blown. Click any fuse to blow or restore it and watch the stored words change.

Some ROMs have an inverter after each OR gate and start with all 0 outputs. For those, keep the fuses of the minterms where the output is 1 in the complemented sense: the OR gate forms F′ and the inverter restores F (Mano Fig. 5-23c).

Example · A 64 × 4 ROM as a lookup table

Scenario. A controller keeps a small table of 4-bit codes in a ROM. The table has room for 64 entries, but only 12 are used: Word 1 to Word 12, each stored at a chosen address. When the controller puts an address on the 6 address lines, the ROM must put the 4-bit word stored there on its outputs. Any address that holds no word must read 0000.

This is the memory view of a ROM: address in, stored word out. Below we program it step by step, then read it back.

Memory map (truth table)

Inputs: address lines A₅ A₄ A₃ A₂ A₁ A₀ (n = 6). Outputs: data bits F₃ F₂ F₁ F₀ (m = 4). Rows are listed in address order.

Programming the ROM

  1. Choose the size. 6 inputs and 4 outputs give a 2⁶ × 4 = 64 × 4 ROM (64 words of 4 bits). Inside it there are two parts:
    • A 6 × 64 decoder. It turns the 6-bit address into 64 lines, m₀ to m₆₃. For any address, exactly one line is 1.
    • 4 OR gates, one per output bit (F₃, F₂, F₁, F₀). Each OR gate is wired to all 64 decoder lines, and every wire passes through its own fuse.
    So the fuses form a grid of 64 lines × 4 OR gates = 256 fuses. An intact fuse lets a line's 1 reach that output; a blown fuse blocks it.
  2. Write the program table. The 12 rows above; every other address stores 0000. No simplification is needed.
  3. Blow the fuses. On each minterm line, keep the fuse (●) to every output whose bit is 1 and blow it (✕) where the bit is 0. On the 52 unused lines, blow all 4 fuses.

Reading the matrix down each column gives every output as a sum of minterms, exactly as in the circuit view of a ROM:

Looking ahead: the same data in a PLA

52 of the 64 words in this ROM hold nothing, yet the decoder still builds all 64 minterm lines. A PLA builds only the product terms it needs: here one AND gate per stored word, P₀ to P₁₁, each matching all six address bits. In the program table, 1 = variable used true, 0 = complemented, and – = no connection.

Fuse count (Mano's formulas): ROM 2ⁿ × m = 64 × 4 = 256. PLA 2n × k + k × m + m = 2·6·12 + 12·4 + 4 = 196, with only 12 AND gates instead of 64 decoder lines. Simplifying the functions could reduce the product terms further; this is why a PLA is preferred when most addresses are don't-cares.

Example · Squaring a 3-bit number with a ROM

Mano Example 5-3: inputs A₂A₁A₀, output = square of the input (0 to 49), so 6 output bits B₅…B₀.

B₀ always equals A₀, and B₁ is always 0, so they need no ROM outputs. Only B₅–B₂ are stored: the ROM needs 3 inputs and 4 outputs, an 8 × 4 ROM.

Two ways to view a ROM. (1) As a circuit: each output is a Boolean function in sum of minterms. (2) As memory: the inputs give an address and the outputs read out the stored word, hence "read-only memory". ROMs are used for code converters, arithmetic functions such as multipliers, character displays, and microprogrammed control units.

Programmable logic array (PLA)

When a circuit has many don't-care conditions, a ROM wastes space: its words at unused addresses are never used. Mano's example: a 12-bit card code to 6-bit internal code would need a 4096 × 6 ROM, yet only 47 words are used. A PLA is an LSI device that avoids this waste. It does not fully decode the inputs: the decoder is replaced by a group of programmable AND gates, each producing one product term, so functions are implemented in simplified sum-of-products form.

A PLA has n inputs, k product terms (AND gates), m outputs (OR gates). Fuses connect every input and its complement to every AND gate, every AND gate to every OR gate, and each output to an inverter that can be bypassed (output true, T) or kept (output complemented, C).

PLA program table

Programming a PLA means specifying its AND-OR-NOT paths. The program table has three parts:

  • Product term: numbered list of the AND gates.
  • Inputs: for each product term, 1 if the variable appears uncomplemented, 0 if complemented, – if absent (no connection).
  • Outputs: 1 if the product term is part of that output, – if not. Under each output, T (true) keeps the inverter bypassed; C (complement) uses it.

Example (Mano Fig. 5-27): three inputs, two outputs. From the truth table, F₁ = Σ(4, 5, 7) and F₂ = Σ(3, 5, 7). Simplify each output to as few product terms as possible:

F₁ = AB′ + AC F₂ = AC + BC

Only three distinct product terms are needed (AC is shared by both outputs), so a PLA with 3 inputs, 3 product terms and 2 outputs is enough.

Optional · beyond syllabus

Programmable array logic (PAL)

A PAL has a programmable AND array and a fixed OR array. It is easier to program than a PLA but less flexible: each OR gate has its own fixed set of AND gates, so product terms cannot be shared between outputs. Each function must be simplified on its own and must fit the number of terms per section. Mano's PAL (Fig. 5-30) has 4 inputs, 4 outputs and sections with 3 AND gates each.

Q4Why is a PLA preferred over a ROM when there are many don't-care conditions?Answer

A ROM always decodes every address, so words for the don't-care addresses are wasted. A PLA only builds the product terms the simplified functions need, and don't-cares help simplify those terms further.

Q5In a PLA program table, what do 1, 0 and – mean in the inputs columns?Answer

1: the uncomplemented variable is connected to that AND gate. 0: the complemented variable is connected. –: no connection (both fuses blown); an open AND input behaves like 1.

5-2Build a BCD-to-Excess-3 converter with a 4-bit adder. How do you change it into an Excess-3-to-BCD converter?Answer

Apply the BCD digit to the A inputs, 0011 to the B inputs and C₁ = 0; the sum outputs give Excess-3. For the reverse, subtract 3: apply the Excess-3 digit to A and add 1101 (2's complement of 0011), ignoring the output carry.

5-3The adder-subtractor computes 0110 − 1001 (6 − 9). Give the nine inputs and five outputs.Optional

Inputs: M = 1, A = 0110, B = 1001. The XOR gates give B′ = 0110 and C₁ = 1. Sum: 0110 + 0110 + 1 = 1101, C₅ = 0. Outputs: S = 1101, C₅ = 0. C₅ = 0 means A < B; 1101 is the 2's complement of 0011, i.e. −3.

5-18Construct a 5 × 32 decoder with four 3 × 8 decoders (with enable) and one 2 × 4 decoder.Answer
