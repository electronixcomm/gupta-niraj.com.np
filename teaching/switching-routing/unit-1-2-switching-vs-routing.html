STRUCTURE FIRST, BEHAVIOR SECOND

How a frame becomes a packet becomes a delivery.

Every message on a network is carried inside two nested envelopes: a frame, addressed to a neighbor, wrapped around a packet, addressed to a destination that might be on the other side of the planet. We'll open both envelopes first, byte by byte — then look at the devices that read them and the decisions those devices make.

FRAME SIZE RULES

Minimum frame: 64 bytes (dest MAC through FCS) — anything smaller is a collision fragment and gets discarded.

Maximum standard frame: 1518 bytes (1522 with an 802.1Q VLAN tag). Anything larger is a "jumbo frame," and needs support on every hop.

HOW THE PIECES CONNECT

IHL tells a router how many 32-bit words the header is (5 = 20 bytes, no options). Protocol tells the receiving host what's inside the payload (6 = TCP, 17 = UDP, 1 = ICMP) — the Layer-3 counterpart to the frame's EtherType. TTL is decremented by every router; a packet stuck in a routing loop dies instead of circulating forever.

BEHAVIOR — PART 1

Switching vs. routing

Now that the envelopes are familiar: both switching and routing are forwarding decisions. The difference is which envelope's address they read, and how far that address can take a message.

Switching Layer 2

Forwards frames using the destination MAC address, within a single LAN segment (one broadcast domain).

  • Learns MAC-to-port mappings automatically by watching source addresses
  • Builds a MAC address table in hardware (ASIC) — very fast, low latency
  • Has no concept of IP addresses or subnets
  • Every port is, by default, in the same network

Routing Layer 3

Forwards packets using the destination IP address, between different networks.

  • Maintains a routing table, built statically or via a protocol (OSPF, BGP, etc.)
  • Picks a path using longest-prefix match, not an exact lookup
  • Each interface sits on a different subnet
  • Decrements TTL, may fragment, may perform NAT

WORTH KNOWING

A Layer 3 switch blurs the line — it switches within VLANs and routes between them, all in hardware. The concepts stay identical; only the box changes.

THE MISSING STEP

How a MAC address is learned in the first place

Every diagram so far assumed the sender already knew the destination MAC. In practice, a host almost never does at first — it has to ask. This is ARP (Address Resolution Protocol): the process that turns a known IP address into an unknown MAC address, and the moment a switch's CAM table actually gets built.

THE ONE FACT TO KEEP

The IP header's source and destination addresses never change in transit. The Ethernet frame wrapped around it is torn off and rebuilt at every single router, because a MAC address is only ever meaningful to your immediate neighbor on the wire.

Full worked example: a ping across two routers

Same idea, traced address-by-address. Host A pings Host B across two subnets joined by two routers — every hop strips one Ethernet frame off and builds a new one, while the IP packet inside rides through untouched.

TOPOLOGY
Host A (Subnet 1)IP 192.168.1.20  ·  MAC AA:AA
Router 1 — Int 1 (gateway)IP 192.168.1.1  ·  MAC BB:BB
Router 1 — Int 2 (link)IP 10.0.0.1  ·  MAC CC:CC
Router 2 — Int 1 (link)IP 10.0.0.2  ·  MAC DD:DD
Router 2 — Int 2 (gateway)IP 172.16.1.1  ·  MAC EE:EE
Host B (Subnet 2)IP 172.16.1.50  ·  MAC FF:FF
1

Host A builds and encapsulates the packet. It checks its routing table, sees 172.16.1.50 is off-subnet, and forwards to its default gateway. Packet: src 192.168.1.20 → dst 172.16.1.50. Frame: src MAC AA:AA → dst MAC BB:BB (Router 1's local interface — not Host B's MAC, which Host A has no way to know yet).

2

Router 1 receives and strips the frame. Destination MAC matches BB:BB, so the Ethernet header is stripped and discarded. It reads the Layer 3 destination (172.16.1.50), finds a route via Interface 2 toward Router 2 (10.0.0.2), and decrements TTL by 1.

3

Router 1 re-encapsulates and forwards. A brand-new frame is built for the router-to-router link. Packet unchanged: src 192.168.1.20 → dst 172.16.1.50. New frame: src MAC CC:CC (R1's exit interface) → dst MAC DD:DD (R2's receiving interface).

4

Router 2 receives and strips the frame. Destination MAC matches DD:DD, so that second Ethernet header is stripped. It reads 172.16.1.50 again and finds that subnet directly connected on its own Interface 2 — no further router needed. TTL is decremented a second time.

5

Router 2 re-encapsulates for local delivery. A third frame is built, this time addressed straight to Host B. Packet still unchanged: src 192.168.1.20 → dst 172.16.1.50. New frame: src MAC EE:EE (R2's gateway interface) → dst MAC FF:FF (Host B's real MAC, learned via ARP on that segment).

6

Host B receives and processes. Destination MAC and IP both match. It strips the final frame, hands the payload up to ICMP, and builds an Echo Reply — running this entire process in reverse to get back to Host A.

CLOSE

Recap

  • An Ethernet frame is a MAC-addressed envelope with an EtherType and a checksum; an IPv4 header is a smaller, structured envelope inside it, addressed by IP with its own TTL and checksum.
  • A switch forwards frames by MAC address inside one LAN; a router forwards packets by IP address between networks.
  • On a LAN, an unknown destination MAC gets flooded; a known one is switched straight to its learned port.
  • Across a WAN, the IP header rides unchanged end-to-end while the Ethernet frame around it is rebuilt at every hop.
