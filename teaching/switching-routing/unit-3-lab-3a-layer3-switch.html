Lab 3A: Inter-VLAN Routing with a Layer 3 (Multilayer) Switch

Packet Tracer · 3560-24PS multilayer switch with SVIs · Problem statement with solution

1. Scenario

A small office has two departments, VLAN 10 and VLAN 20, each with its own DHCP server and two laptops. Everything connects to one multilayer switch. Instead of buying a router, you will let the switch route between the VLANs. Each VLAN gets a virtual interface (SVI) that acts as the default gateway, and the switch's ip routing feature forwards traffic between them in hardware.

Learning objectives

  • Create VLANs and assign access ports on a multilayer switch.
  • Enable layer 3 routing with ip routing and create SVIs.
  • Configure DHCP servers inside each VLAN.
  • Verify inter-VLAN connectivity and compare this method with router-on-a-stick.

Part 1Build and cable the network

  1. Place one 3560-24PS multilayer switch, four laptops and two servers. Rename the servers "DHCP for Vlan 10" and "DHCP server for vlan 20".
  2. Connect every device to the switch with a straight-through cable, using the ports in the VLAN plan.
Checkpoint: All six links turn green. There is no router and no trunk in this lab.

Part 2Create VLANs and assign access ports

  1. Create VLANs 10 and 20.
  2. Put Fa0/1–3 in VLAN 10 and Fa0/4–6 in VLAN 20 as access ports.
Checkpoint: show vlan brief lists Fa0/1–3 under VLAN 10 and Fa0/4–6 under VLAN 20.

Part 3Enable routing and create the SVIs

  1. Turn on layer 3 routing on the switch.
  2. Create interface vlan 10 and interface vlan 20 with the gateway addresses from the plan, and bring them up.
Checkpoint: show ip interface brief shows Vlan10 and Vlan20 up/up, and show ip route lists C 192.168.1.0/24 and C 192.168.2.0/24.

An SVI comes up only when its VLAN exists and at least one active port is in that VLAN. If the SVI shows up/down, check the VLAN and the cabling first.

Part 4Configure the DHCP servers

  1. On each server set a static IP, mask and default gateway (the SVI address of its VLAN).
  2. Turn the DHCP service on and set the pool: default gateway = SVI address, start address .10, mask 255.255.255.0, maximum 50 users, then click Save.
Checkpoint: The server's device info shows its address and gateway, and each Services > DHCP page shows Service On with its pool.
Show solution (GUI screenshots)

Here the pool is the built-in serverPool, edited to the values above. Because the server is in the same VLAN as its clients, no ip helper-address is needed: the clients' broadcasts reach the server directly (see the concept note in Part 5).

Part 5Verify inter-VLAN routing

  1. Set Laptop1 to Laptop4 to DHCP and record their addresses and gateways.
  2. Ping within a VLAN (Laptop1 to Laptop2) and across VLANs (Laptop1 to Laptop3 and Laptop4).
  3. Ping each server from a laptop in the other VLAN, then run tracert from Laptop1 to Laptop3.
Checkpoint: VLAN 10 laptops receive 192.168.1.x and VLAN 20 laptops 192.168.2.x. All pings succeed (the first one may time out while ARP resolves). The traceroute shows 192.168.1.1, then the destination.

  • SVI up/down: the VLAN is missing or no active port is in it.
  • Cross-VLAN ping fails: ip routing is off (it is disabled by default on the 3560), or a host gateway is wrong.
  • No DHCP address: the server's service is Off, its pool does not match the VLAN subnet, or the server is on the wrong VLAN port.
Concept note: SVIs, ip routing and why no helper-address
  • SVI: a virtual layer 3 interface for a VLAN. It is the default gateway for that VLAN's hosts.
  • ip routing: without it the 3560 behaves like a layer 2 switch and will not route between its SVIs.
  • No helper needed: DHCP broadcasts stay inside the VLAN and the server is in the same VLAN. Add ip helper-address on the SVI only if the DHCP server is in a different VLAN or subnet (as in Lab 3B).
