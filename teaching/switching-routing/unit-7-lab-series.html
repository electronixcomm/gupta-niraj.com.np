Unit 7 · Lab series · 6 short labs · about 4 hours

Mini mobile network: one core, two cell sites

A small mobile operator connects two cell sites to its core with three switches. The network carries 4G, 3G and GSM traffic in separate VLANs. You will build it, make it loop-free, secure the cell-site ports, bundle two links, and fix faults. Only 6 end devices and 3 ping tests are needed.

4G · 4 VLANs 3G · 2 VLANs GSM · 1 VLAN MGMT 99 · NATIVE 999 Packet Tracer · 3 × 2960 · 3 PCs · 3 Servers

Lab 2 · 45 min

Observe STP and choose the root bridge

7.1 · 7.2
TASK

The core switch must be the root

Today the root is chosen by chance (lowest MAC). Make CORE-SW1 the root for all VLANs and SITE-B the backup.

Part A · Predict, then check

All switches are at priority 32768. Example MACs (yours will differ): CORE-SW1 0001.42A7.A603, SITE-B 0030.F222.2794, SITE-A 000A.41D5.7937. For VLAN 110, which switch is root and which ports block?

Reveal

CORE-SW1 is root (lowest MAC). SITE-A and SITE-B both use their Fa0/1 as root port (cost 19; the other way is 4 + 19 = 23). On the gigabit links both have cost 19, so the lower bridge ID wins: SITE-A (000A…) beats SITE-B (0030…), so SITE-B Gi0/1 and Gi0/2 block.

CORE-SW1# show spanning-tree vlan 110   ! look for "This bridge is the root"
SITE-A# show spanning-tree vlan 110     ! Root ID vs Bridge ID, root port, Altn BLK ports
SITE-A# show cdp neighbors              ! which switch is on the root port?

Part B · Set the root

CORE-SW1(config)# spanning-tree vlan 99,110,120,130,140,210,310,320,999 root primary
SITE-B(config)# spanning-tree vlan 99,110,120,130,140,210,310,320,999 root secondary

Now SITE-B (28672 + 110 = 28782) beats SITE-A, so SITE-A's Gi ports block. CORE-SW1's priority is 24576 + 110 = 24686. Confirm with show spanning-tree summary on CORE-SW1: "Root bridge for: VLAN0099 VLAN0110 …".

Part C · Failure test

  1. On eNB-01 run ping -t 10.11.0.1.
  2. On CORE-SW1, shutdown Fa0/2. SITE-A must now reach the root through SITE-B.
  3. Count lost pings. With PVST+ (802.1D) expect about 30 s (listening 15 s + learning 15 s).
  4. no shutdown Fa0/2.
Optional challenge: a different root per VLAN (PVST+)

Make SITE-B root for the GSM and 3G VLANs so the gigabit links carry them:

SITE-B(config)# spanning-tree vlan 210,310,320 root primary
CORE-SW1(config)# spanning-tree vlan 210,310,320 root secondary

Check show spanning-tree vlan 210 on SITE-A: the root port becomes Gi0/1 (cost 4), and CORE-SW1 Fa0/2 now blocks for VLAN 210. Each VLAN has its own tree. Undo it before Lab 3 so the expected outputs match.

Lab 3 · 35 min

Rapid PVST+, PortFast and BPDU Guard

7.2
TASK

Faster recovery and protected cell-site ports

A 30 s outage drops calls. Switch to Rapid PVST+. Make device ports come up instantly, and shut any device port where someone plugs in a switch.
CORE-SW1(config)# spanning-tree mode rapid-pvst
CORE-SW1# show spanning-tree vlan 110        ! protocol rstp

Repeat the Lab 2 failure test. Expect to lose about one ping instead of about 30.

SITE-A(config)# interface range fa0/5 - 6
SITE-A(config-if-range)# spanning-tree portfast
SITE-A(config-if-range)# spanning-tree bpduguard enable

Test BPDU Guard

  1. Unplug BTS-01 from SITE-A Fa0/6 and plug a spare switch into that port.
  2. The console shows %SPANTREE-2-BLOCK_BPDUGUARD … Disabling port. Check with show interfaces status err-disabled.
  3. Remove the spare switch, reconnect BTS-01, then shutdown and no shutdown on Fa0/6. Ping BSC again.

Lab 4 · 40 min

Port security on the eNodeB port

7.3
TASK

Only the eNodeB may use its port

Lock SITE-A Fa0/5 to eNB-01 with a sticky MAC, then test what each violation mode does when another device connects.

Part A · Sticky MAC

SITE-A(config)# interface fa0/5
SITE-A(config-if)# switchport port-security
SITE-A(config-if)# switchport port-security maximum 1
SITE-A(config-if)# switchport port-security mac-address sticky
SITE-A(config-if)# switchport port-security violation shutdown
! ping 10.11.0.1 from eNB-01 so its MAC is learned
SITE-A# show port-security interface fa0/5
SITE-A# show running-config interface fa0/5   ! sticky MAC line is now there
SITE-A# copy running-config startup-config

Part B · Cause a violation and compare modes

  1. On eNB-01 open Config → FastEthernet0 and change the MAC (for example 0001.1111.2222). Ping again.
  2. shutdown: port goes err-disabled, status Secure-shutdown, violation count 1. Restore the MAC, then shutdown / no shutdown.
  3. Set switchport port-security violation restrict and repeat: port stays up, wrong MAC is dropped, a log message appears and the counter goes up.
  4. Set switchport port-security violation protect and repeat: port stays up, wrong MAC dropped silently, no log, no counter.

Part C · Aging (BTS port)

A field engineer sometimes connects a laptop alongside BTS-01. Allow 2 dynamically learned addresses and remove any address that is idle for 10 minutes.

Lab 5 · 40 min

EtherChannel between the cell sites

7.4
TASK

Make two gigabit links act as one

STP blocks one of the two links between SITE-A and SITE-B. Bundle them into Port-channel 1 with LACP.
SITE-B(config)# interface range gi0/1 - 2
SITE-B(config-if-range)# channel-group 1 mode active
SITE-B(config-if-range)# interface port-channel 1
SITE-B(config-if)# switchport mode trunk
SITE-B(config-if)# switchport trunk native vlan 999
SITE-A(config)# interface range gi0/1 - 2
SITE-A(config-if-range)# channel-group 1 mode passive
SITE-A(config-if-range)# interface port-channel 1
SITE-A(config-if)# switchport mode trunk
SITE-A(config-if)# switchport trunk native vlan 999
SITE-B# show etherchannel summary
Group  Port-channel  Protocol    Ports
------+-------------+-----------+------------------------
1      Po1(SU)         LACP      Gig0/1(P) Gig0/2(P)
SITE-A# show spanning-tree vlan 110
Fa0/1            Root FWD 19        128.1    P2p
Po1              Altn BLK 3         128.27   Shr

STP now sees one port, Po1, not two. Po1 is still blocked at SITE-A because the direct uplink to the root is cheaper (19 vs 3 + 19). EtherChannel removes blocking inside the bundle, not between different paths. (Packet Tracer may show a different cost for Po1.)

Tests

  1. Use the bundle: shut CORE-SW1 Fa0/2 so SITE-A must use Po1. Start ping -t 10.11.0.1 on eNB-01, then shut SITE-B Gi0/1. No pings are lost: Po1 stays up on Gi0/2. Restore both ports.
  2. Wrong modes: set SITE-B to passive too. The channel fails and the ports show (I) stand-alone. Set it back to active.
  3. PAgP: no interface port-channel 1 on both, then channel-group 1 mode desirable on SITE-B and auto on SITE-A. Protocol shows PAgP.
  4. Mismatch: on SITE-A Gi0/2 set speed 100. That member shows (s) suspended. Undo with speed auto.
Optional: Layer 3 EtherChannel (router ↔ 3560)

The IP address goes on the port-channel, not on the member ports.

Router(config)# interface port-channel 1
Router(config-if)# ip address 10.200.0.1 255.255.255.252
Router(config-if)# interface range g0/0 - 1
Router(config-if-range)# channel-group 1

On the 3560: no switchport on the members and on Po1, then ip address 10.200.0.2 255.255.255.252 on Po1. show etherchannel summary shows Po1(RU), where R means Layer 3.
