Routing Principles, Routing Tables & Static Routes

How a router decides where a packet goes next, what it stores to make that decision, and how administrative distance settles disagreements between sources.

Section 4.1
00

By the end of this hour

  • Explain what a router's job actually is, in terms of the routing table it builds and consults.
  • Read a routing table entry and name each field: destination network, mask, next hop, exit interface, source, metric.
  • Explain longest prefix match and use it to predict which route a router will choose.
  • Write the ip route command correctly for a given topology.
  • Define administrative distance and explain why it exists, using it to resolve conflicts between routing sources.
―

How the pieces fit together

"Routing principles" is the umbrella term for this whole hour — not a single rule. It breaks into three questions, asked in the order a router actually asks them. Everything below unpacks one branch at a time.

01

Fundamentals: what a router actually does

Strip away the configuration syntax and a router does one repeating job: for every packet it receives, decide which interface to send it out of next. It never sees the whole path to the destination — only the next hop. That decision, made fresh for every packet, is routing.

A router builds its decision-making reference — the routing table — from up to three kinds of information:

  • Directly connected networks — interfaces the router owns, learned automatically the moment an interface is up and addressed.
  • Static routes — paths an administrator types in by hand.
  • Dynamic routing protocols — paths routers learn from one another automatically (RIP, OSPF, EIGRP — covered in later units).

Today's session covers the first two. Every route, however it's learned, ends up as one row in the same table, competing on equal footing whenever more than one source offers a path to the same place.

Anatomy of a routing table entry

Below is a small internetwork and the routing table one of its routers builds from it. Each row answers the same question: to reach this network, send the packet out this interface, toward this neighbor.

R1 knows about 10.0.1.0/24 and the point-to-point link automatically, because it owns those interfaces. It only knows how to reach 10.0.2.0/24 — LAN B, hanging off R2 — because someone typed a static route telling it to.

02

Path selection: which matching row wins

A destination address can match several rows in the table at once. Routers always resolve that with the same rule.

Longest prefix match

Given several candidate routes that all cover a destination address, the router chooses the one with the longest matching prefix — the most specific network, i.e. the largest subnet mask. A more specific route always wins over a more general one, regardless of which source it came from or its administrative distance.

FIG 2 · packet to 10.0.2.15 checked against three candidate rows

If the match is still tied

If two or more sources offer a route with the same prefix length, the tie is broken by administrative distance first, and then, if the AD also matches, by the routing protocol's own metric (hop count, bandwidth, cost — depends on the protocol). We'll build the AD comparison in a moment.

COMMON MIX-UP · AD compares sources, not paths

A single routing protocol can learn several paths to the same network — that's not what AD is for. AD only activates when two different sources (e.g. a static route and OSPF) offer a route to the identical prefix and mask. Within one source, multiple paths are compared by that protocol's own metric, never by AD, because routes from the same source already carry the same AD and there's nothing left to break the tie with.

SituationResolved by
Different prefix lengths, any sourceLongest prefix match — checked first, always
Same prefix, different sourcesAdministrative distance — lower wins
Same prefix, same source, multiple pathsThe source's own metric (hop count, cost, bandwidth…)
03

Arbitration: static routes and administrative distance

Writing a static route

A static route tells the router, in one line, how to reach a network it doesn't own. Using R1 from Figure 1:

R1(config)# ip route 10.0.2.0 255.255.255.0 10.0.12.2 ^destination ^mask ^next-hop address

The same route can instead point out a local exit interface rather than a neighbor's address — useful on point-to-point links:

R1(config)# ip route 10.0.2.0 255.255.255.0 g0/1

A default static route covers "anything not otherwise matched" and is written with an all-zero network and mask:

R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.2

Why administrative distance exists

A router can learn a route to the same network from more than one source at once — say, a static route an admin typed and an OSPF advertisement from a neighbor, both for 10.0.2.0/24. Both can't go in the table if their prefix length ties. Administrative distance (AD) is a per-source trust rating from 0–255 that a router uses to pick one: lower AD wins. It rates the source, not the path — it never compares two paths coming from the same protocol, only two competing sources claiming the same prefix. It is also purely local and never advertised to other routers — it only affects which source this one router trusts.

FIG 3 · default administrative distances (lower = more trusted)

Notice a static route (AD 1) beats every dynamic protocol by default. That's deliberate: if an administrator bothered to type a path by hand, IOS assumes it should override anything a routing protocol figures out on its own — unless the admin sets a higher AD on that static route on purpose (a floating static route, used as a backup path that only appears if the primary dynamic route disappears).

Worked conflict

R1 has a static route to 10.0.2.0/24 (AD 1) and also receives an OSPF advertisement for the same /24 (AD 110). Same prefix length, so it's not a longest-prefix-match case — it comes down to AD. The static route stays in the table; the OSPF route is discarded, even though the OSPF path might genuinely be shorter. This is the most common real-world reason a "clearly better" dynamic path gets ignored, and it's worth checking show ip route for stale static entries before blaming the routing protocol.

04

Terms to lock in before the next class

Routing table

The list a router builds and consults to choose an exit interface and next hop for every packet.

Longest prefix match

Among all matching routes, the router always prefers the one with the most specific (longest) subnet mask.

Administrative distance

A local, per-source trust value (0–255) used to break ties when two sources offer routes with the same prefix length. Lower wins.

Floating static route

A static route deliberately configured with a higher AD than the primary dynamic protocol, so it only activates as a backup.

05

Check-in questions (last 10 minutes)

Pose these to the class before showing the next unit's dynamic routing content — they surface the misconceptions worth catching now.

Q1

A router has two routes to the same destination network with the same subnet mask: one static (AD 1) and one learned via RIP (AD 120). Which one goes in the routing table, and why?

Reveal answer
The static route. Same prefix length means it's not a longest-prefix-match situation, so the router falls back to administrative distance, and lower AD (1 < 120) wins.
Q2

Why does a router never share its administrative distance values with neighboring routers?

Reveal answer
AD is a purely local preference a router uses to decide which of its own information sources to trust — it isn't a property of the route itself, so it has no meaning outside that one router and is never advertised.
Q3

A packet's destination matches both a default route (0.0.0.0/0) and a specific static route (10.0.2.0/24). Which wins, and does AD even come into it?

Reveal answer
The specific /24 route wins on longest prefix match alone. AD is never consulted here, because the two routes don't tie on prefix length — AD only matters when prefix length is equal.

Default Routes & Stub Networks

Why a router with only one way out doesn't need a routing table at all — and how one line covers "everything else."

Section 4.2
00

By the end of this session

  • Define a default route, recognize its 0.0.0.0/0 notation, and explain why it always matches.
  • Write a default static route using either a next-hop address or an exit interface.
  • Define a stub network and explain why a router at the edge of one never needs a full routing table.
  • Identify the gateway of last resort in a given show ip route output.
  • Predict what happens to an unmatched packet with and without a default route present.
01

The route that matches everything

Every route in a table covers some slice of address space. A default route is the one exception written to cover all of it — the catch-all a router falls back on when nothing more specific applies.

It is written with an all-zero network and an all-zero mask, which is why it's often called the quad-zero route:

R3(config)# ip route 0.0.0.0 0.0.0.0 10.0.13.1 ^covers every network ^next-hop toward the rest of the internetwork

Because the mask is /0, it is the least specific route that could ever exist — from Unit 4.1's longest-prefix-match rule, it always loses to any more specific route, and only gets used when nothing else in the table matches the destination at all.

FIG 1 · where the default route sits in the match order

When a router installs a default route, show ip route reports it as the gateway of last resort and marks the source line with S* (or the appropriate code) rather than plain S.

R3# show ip route Gateway of last resort is 10.0.13.1 to network 0.0.0.0 S* 0.0.0.0/0 [1/0] via 10.0.13.1 C 10.0.3.0/24 is directly connected, GigabitEthernet0/0 C 10.0.13.0/30 is directly connected, GigabitEthernet0/1
02

Stub networks: when one route is enough

A stub network is one with exactly one way in and out — a single uplink connecting it to the rest of the internetwork. A branch office, a small campus building, or a customer edge site are typical examples.

A router sitting at the edge of a stub network never needs to know the individual identity of every remote network beyond its uplink — there's only one direction "away" could ever mean. So instead of learning (or being manually configured with) dozens of specific routes, it needs exactly one: a default route pointing out its single exit.

FIG 2 · a branch router with one uplink needs no routing table beyond a default

That single line replaces what would otherwise be a full, constantly-updated table of every remote subnet — and it never goes stale, because "everything not local" doesn't change even as the rest of the network grows.

COMMON MIX-UP · stub network vs. stub router vs. stub area

This unit's "stub network" is a topology description — a site with one uplink — solved with a plain default static route. Later, in dynamic routing units, you'll meet OSPF's formal stub area, a related but distinct configuration where a router still runs OSPF but is told to accept a summarized default instead of full external routes. Don't conflate the two yet; today's stub networks need no routing protocol at all.

03

Worked example: configuring the branch router

Using R3 from Figure 2, the branch has one local LAN and one uplink to headquarters. The full configuration needed to make LAN C fully reachable to and from the rest of the enterprise is just:

R3(config)# ip route 0.0.0.0 0.0.0.0 10.0.13.1

Two things still have to be true for this to work end-to-end, and both are worth checking explicitly in a lab:

  • R1 (the hub) must have a specific route back to 10.0.3.0/24 — either static or learned dynamically. A default route only solves the outbound half; the hub still needs to know how to send replies back to the branch.
  • The hub's own default or upstream route handles anything beyond it, so the default-route pattern often repeats hop by hop toward the network's actual edge (e.g. an internet-facing router).

Default route

A route with network and mask both 0.0.0.0, matching any destination not covered by a more specific entry.

Gateway of last resort

The next hop a router uses when no other route matches; shown at the top of show ip route output when a default route is installed.

Stub network

A network reachable through exactly one exit path, so a single default route fully describes how to leave it.

Quad-zero route

Informal name for the default route, from its 0.0.0.0 0.0.0.0 notation.

04

Check-in questions (last 5 minutes)

Q1

Why does a default route never win a match if a more specific route also matches the same destination?

Reveal answer
Its mask is /0 — the least specific possible — so under longest-prefix-match (4.1), any route with a longer mask that also matches is always preferred over it.
Q2

A stub router's LAN can reach headquarters, but replies never come back. The stub's default route is configured correctly. What's the most likely cause?

Reveal answer
Headquarters is missing a route back to the stub's LAN. A default route only solves outbound routing at the stub; the far end still needs a specific (or its own default) route home.
Q3

Why doesn't a stub network's routing need to be updated when new subnets are added elsewhere in the enterprise?

Reveal answer
The stub router's only route is "everything else, out this one exit" — that statement stays true no matter how many subnets exist beyond it, so nothing at the stub needs to change.

Advantages & Disadvantages of Static Routing

Static routing isn't a lesser version of dynamic routing — it's a different trade-off, and the right choice depends entirely on what the network needs to do.

Section 4.3
00

By the end of this session

  • List the main advantages of static routing and explain the mechanism behind each one.
  • List the main disadvantages of static routing and explain why they get worse as a network grows.
  • Given a short network scenario, judge whether static or dynamic routing is the better fit, and justify the choice.
01

What static routing gets you

Every advantage of static routing comes from the same root cause: nothing is being computed or exchanged at runtime. The path was decided once, by a human, and the router simply obeys it.

AdvantageWhy it happens
Predictable pathThe route never changes on its own, so traffic always takes the exact path the administrator chose — useful when a specific link must carry specific traffic.
No routing protocol overheadNo periodic updates, no neighbor relationships, no CPU spent recalculating paths — every cycle a dynamic protocol would use is saved.
Lower bandwidth useNothing is advertised between routers, so links carry only actual traffic, not routing-protocol chatter.
Tighter security postureWith no routing protocol running, there's no protocol to spoof, inject false routes into, or eavesdrop on.
Simple to configure at small scaleA handful of ip route lines is easier to write, read, and audit than tuning a routing protocol, when the topology is small.
Works with any adjacent deviceThe next-hop router doesn't need to speak the same routing protocol — it doesn't need to run one at all.
02

What it costs you

The same lack of automation that makes static routing lean also makes it brittle. Every disadvantage below is the flip side of an advantage above.

DisadvantageWhy it happens
Doesn't scaleEvery reachable network needs its own manually typed line; a network with hundreds of subnets means hundreds of routes to write and keep correct.
No automatic failoverIf the configured next hop or link goes down, the static route stays in the table pointing at a dead path until a human fixes it — there's no protocol reconverging around the failure.
Manual maintenance on every topology changeAdding a subnet, removing a link, or renumbering anything means visiting every router whose table referenced it.
Error-prone at scaleHand-typed configuration invites typos in addresses and masks — mistakes a dynamic protocol would never make, because it computes the routes itself.
No load-aware path choiceA static route can't shift traffic based on current link utilization or congestion; it always sends packets the one way it was told, regardless of conditions.
WORTH REMEMBERING · the failure mode is silent

A dynamic routing protocol fails loudly — a neighbor relationship drops, and the table updates within seconds. A static route fails silently: the entry stays in the table, looking perfectly valid, pointing at a next hop that may no longer exist. This is why static-heavy networks lean so heavily on the troubleshooting tools in 4.4 — nothing will tell you a static route is wrong except checking it yourself.

03

Choosing between static and dynamic

Neither approach is universally "better" — each fits different network shapes. In practice, most real networks use both together: static routes at the stable, simple edges, and a dynamic protocol in the complex, changeable core.

ScenarioBetter fit
Small network, few routers, topology rarely changesStatic — the overhead of a routing protocol isn't justified
Stub network with exactly one exit (4.2)Static — a single default route is simpler and never goes stale
Backup path, only used if the primary failsStatic (floating static, from 4.1) — deliberately controlled, predictable fallback
Large network, many routers, frequent changesDynamic — manual maintenance would be constant and error-prone
Network needs automatic rerouting around failuresDynamic — only a routing protocol reconverges without human intervention

Hold onto that last row for the units ahead: dynamic protocols exist specifically to solve the two problems static routing can't — scale and automatic failover.

04

Check-in questions (last 5 minutes)

Q1

A static route's next hop goes down. What does the routing table show, and what actually happens to traffic?

Reveal answer
The static route stays in the table exactly as configured — nothing removes it automatically — but traffic sent toward that dead next hop is dropped, since the path no longer exists.
Q2

Why is static routing described as having "no routing protocol overhead" — what specifically is being saved?

Reveal answer
CPU cycles that would otherwise go to running a protocol and recalculating paths, and bandwidth that would otherwise carry periodic route advertisements between routers.
Q3

A company is adding a new subnet every week to a fast-growing data center core. Would you recommend static or dynamic routing there, and why?

Reveal answer
Dynamic. Frequent topology changes mean constant manual updates under static routing, which doesn't scale and invites configuration errors; a dynamic protocol adapts to the changes automatically.

Troubleshooting Static Routing

Three tools, used in order — check what the router believes, check whether the path actually works, then find exactly where it breaks.

Section 4.4
00

By the end of this session

  • Use show ip route to confirm whether a static route is present and installed as expected.
  • Use ping to test end-to-end reachability and correctly interpret success, timeout, and unreachable results.
  • Use traceroute to isolate the exact hop where a path breaks down.
  • Diagnose the most common static-routing faults: missing route, wrong next hop, and missing return path.
01

Start with what the router believes

Before testing anything on the wire, check the router's own understanding of the network. If the route isn't in the table, no amount of pinging will explain why traffic fails — the router was never going to send it the right way.

R1# show ip route Gateway of last resort is not set C 10.0.1.0/24 is directly connected, GigabitEthernet0/0 C 10.0.12.0/30 is directly connected, GigabitEthernet0/1

Compare that against what's expected: if a static route to 10.0.2.0/24 was configured but doesn't appear here at all, the configuration itself is the fault — commonly a typo in the network, mask, or next hop that IOS silently refused to install.

FIG 1 · three things to check in the output, in order
02

ping: does the path work end to end?

ping sends an ICMP echo request and waits for an echo reply. It answers one question — can a packet make the full round trip? — and nothing about where a failure happens along the way.

R1# ping 10.0.2.15 Sending 5, 100-byte ICMP Echos to 10.0.2.15, timeout is 2 seconds: !!!!! Success rate is 100 percent (5/5)
ResultWhat it means
! ! ! ! !Full round trip succeeded — forward and return paths both work.
. . . . .Request timed out — the packet went somewhere but no reply came back in time. Common cause: the return path is missing (see the panel below).
U U U U UDestination unreachable — a router along the path has no route at all and said so explicitly, rather than just going silent.
CLASSIC STATIC-ROUTING GOTCHA · asymmetric routing

A ping can fail even when the static route you just configured is perfect. If R1 has a static route to R2's LAN but R2 has no route back to R1's LAN, R1's echo requests arrive fine — but R2 has nowhere to send the replies. The symptom is a full set of timeouts (. . . . .), and the fix is always to check show ip route on both ends, not just the one you're testing from.

03

traceroute: where exactly does it stop?

Where ping gives a yes/no answer, traceroute shows the whole path, hop by hop — by sending packets with an increasing TTL and reading the "TTL expired" message each router sends back on its way through.

R1# traceroute 10.0.2.15 Tracing the route to 10.0.2.15 1 10.0.12.2 4 msec 4 msec 4 msec 2 * * * 3 * * *

Reading this: hop 1 (R2, the next-hop router) responded normally, so the link between R1 and R2 is fine and R2 has a route back to R1's side. Everything past hop 1 times out — the break is beyond R2, so that's exactly where the investigation should continue, not back at R1.

FIG 2 · ping vs. traceroute — what each tool actually tells you
Questionpingtraceroute

04

Worked scenario: putting the three together

Symptom: a user on LAN A can't reach a server on LAN B. Walk it in order:

  1. show ip route on R1 — the static route to LAN B's subnet is present, correct network, correct mask, next hop 10.0.12.2. Configuration looks right, so the fault is somewhere on the path, not in this line.
  2. ping from R1 to the server — five timeouts. The path isn't fully working, but this alone doesn't say where.
  3. traceroute from R1 — hop 1 (R2) responds; nothing beyond it does. The break is past R2.
  4. show ip route on R2 — no route back to LAN A's subnet at all. Found it: R2 can receive the request but has nowhere to send the reply.
  5. Fix: add the missing static route on R2, then re-run the ping to confirm five replies instead of five timeouts.

Notice the order was never arbitrary: check the configuration first (cheap, instant), confirm there's a real symptom second (ping), then localize it third (traceroute) — only then start changing configuration.

Gateway of last resort not set

Appears in show ip route when no default route is installed — unmatched destinations will be dropped, not forwarded anywhere.

Destination unreachable (U)

A router explicitly reported it has no route to the destination, distinct from a silent timeout.

TTL expired

The message a router sends back when a packet's time-to-live hits zero at that hop — the mechanism traceroute exploits to map the path.

Asymmetric routing fault

Forward path works but the return path is missing a route — the single most common static-routing troubleshooting scenario.

05

Check-in questions (last 5 minutes)

Q1

A ping returns five timeouts (. . . . .) rather than five successes. What does that specifically tell you, and what doesn't it tell you?

Reveal answer
It tells you the round trip didn't complete in time — something failed somewhere. It does not tell you where; that requires traceroute or checking routes hop by hop.
Q2

traceroute shows a reply from hop 1 but nothing from hop 2 onward. Which router should you investigate first?

Reveal answer
Hop 2 (and its own routing table/next hop) — hop 1 responded, so the path and routing up to that router are confirmed working; the fault is between hop 1 and hop 2.
Q3

A static route looks perfectly correct in show ip route, yet ping still fails. Why should you check the far router's routing table next, not the near one's?

Reveal answer
Because the near router's route only covers the outbound half of the trip; if the far router has no route back, replies never return, and the failure is on the far end, not the one you already verified.
