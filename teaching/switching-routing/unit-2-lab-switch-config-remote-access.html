Lab 2: Initial Switch Configuration, Remote Access Setup and Testing Connectivity

1. Scenario

A branch office has just received a new, unconfigured switch. The network team must set it up before it goes into the wiring closet: give it a name and a warning banner, protect it with passwords, assign it a management IP address, and make it manageable from the administrator's laptop without walking to the closet. They must enable secure SSH access, decide whether to keep Telnet as a legacy fallback, and finally test and save the configuration.

The switch connects three devices on 192.168.1.0/24, as in Lab 1. The administrator's PC0 configures it first through the console cable. Laptop0 is used later for remote access.

Learning objectives

  • Use the console connection and move between IOS modes (user EXEC, privileged EXEC, global configuration).
  • Configure the hostname, banner, console security, enable secret and password encryption.
  • Give the switch a management IP address on VLAN 1.
  • Configure SSH (RSA 2048, version 2) and Telnet remote access with local accounts, and explain why SSH is preferred.
  • Test connectivity, verify the configuration and save it.

Solid lines are copper straight-through cables to Fa0/1 (PC0), Fa0/2 (Server0) and Fa0/3 (Laptop0). The dashed line from PC0 is the console (rollover) cable to the switch console port.

Part 1Build the network and connect by console

  1. Place UniGlobe-Main-Switch (2960-24TT), PC0, Server0 and Laptop0. Connect PC0, Server0 and Laptop0 to Fa0/1, Fa0/2 and Fa0/3 with straight-through cables.
  2. Connect PC0's RS232 port to UniGlobe-Main-Switch's Console port with a console (rollover) cable.
  3. Set the three hosts' IP addresses and masks. On PC0 open Desktop > Terminal and connect using the default settings.
Checkpoint: The terminal on PC0 shows the Switch> prompt (press Enter if it is blank).
Show solution
  • Terminal settings: 9600 bits per second, 8 data bits, no parity, 1 stop bit, flow control none.
  • Host IPs: PC0 192.168.1.2, Server0 192.168.1.3, Laptop0 192.168.1.4, all with mask 255.255.255.0 (Config > FastEthernet0 > Static).
  • The console cable is the only way to configure a brand-new switch because it has no IP address or passwords yet.

Part 2Basic switch configuration

  1. Move from user EXEC to privileged EXEC and then to global configuration mode.
  2. Set the hostname, stop the switch from treating mistyped commands as hostnames, and add a warning banner.
Checkpoint: The prompt changes to UniGlobe-Main-Switch(config)#. A mistyped command returns an error immediately instead of a long DNS delay.
Show solution
Switch> enable
Switch# configure terminal
Switch(config)# hostname UniGlobe-Main-Switch
UniGlobe-Main-Switch(config)# no ip domain-lookup
UniGlobe-Main-Switch(config)# banner motd #Authorized access only. Disconnect now if you are not authorized.#
  • User EXEC (>) allows limited viewing. Privileged EXEC (#) allows all show and copy commands. Global configuration changes the whole device.
  • no ip domain-lookup stops the switch from trying to resolve a mistyped word as a hostname.

Part 3Secure console access

  1. Check the console line with show line console 0 and note its number and speed.
  2. Set a console password, require login, keep log messages from interrupting typing and disconnect idle sessions after 10 minutes.
  3. Encrypt the plain-text passwords stored in the configuration.
Checkpoint: Log out of the console (exit) and back in: the switch asks for UniGlobe2026. In show running-config the console password appears as password 7 ..., not in clear text.
Show solution
UniGlobe-Main-Switch# show line console 0
UniGlobe-Main-Switch# configure terminal
UniGlobe-Main-Switch(config)# line console 0
UniGlobe-Main-Switch(config-line)# password UniGlobe2026
UniGlobe-Main-Switch(config-line)# login
UniGlobe-Main-Switch(config-line)# logging synchronous
UniGlobe-Main-Switch(config-line)# exec-timeout 10 0
UniGlobe-Main-Switch(config-line)# exit
UniGlobe-Main-Switch(config)# service password-encryption
  • login makes the line ask for its password. Without it the password is never checked.
  • logging synchronous redraws your typing after a log message so commands are not split.
  • exec-timeout 10 0 is the default, so it will not appear in show running-config. It still protects an unattended console.
  • service password-encryption converts line passwords to type 7. This is reversible and only stops shoulder-surfing, so it is not real protection.

Concept note: why does a layer 2 switch need an IP address?

A switch forwards frames by MAC address and needs no IP to do so. The address belongs to a virtual interface (the SVI) and is used only for management: remote login, ping from the switch, and SNMP or syslog later. The ip default-gateway command lets the switch answer admins on other subnets. It has no effect here because there is no router yet.

Part 5Remote access: privileged mode, SSH and Telnet

  1. Protect privileged mode with an enable secret.
  2. Create the local user admin (privilege 15), set the domain name uniglobe.com.np, generate a 2048-bit RSA key and enforce SSH version 2.
  3. Configure the VTY lines (0 to 15) to authenticate against the local user database, with logging synchronous and a 10-minute timeout. Allow SSH only and test from Laptop0 with ssh -l admin 192.168.1.10.
  4. Allow Telnet as a legacy fallback with transport input telnet ssh and test telnet 192.168.1.10 from Laptop0.
  5. Decide whether Telnet should stay. If not, return the lines to SSH only.
Checkpoint: show ip ssh reports SSH enabled, version 2. Laptop0 logs in over SSH with admin / UniGlobe2026 and sees the banner. Telnet is refused in step 3 and works in step 4.
Show solution: privileged mode and SSH
UniGlobe-Main-Switch(config)# enable secret UniGlobe2026
UniGlobe-Main-Switch(config)# ip domain-name uniglobe.com.np
UniGlobe-Main-Switch(config)# username admin privilege 15 secret UniGlobe2026
UniGlobe-Main-Switch(config)# crypto key generate rsa general-keys modulus 2048
UniGlobe-Main-Switch(config)# ip ssh version 2
UniGlobe-Main-Switch(config)# line vty 0 15
UniGlobe-Main-Switch(config-line)# password UniGlobe2026
UniGlobe-Main-Switch(config-line)# login local
UniGlobe-Main-Switch(config-line)# logging synchronous
UniGlobe-Main-Switch(config-line)# exec-timeout 10 0
UniGlobe-Main-Switch(config-line)# transport input ssh
UniGlobe-Main-Switch(config-line)# exit

Key generation needs the hostname and the domain name set first. A 2048-bit key satisfies the minimum of 768 bits for SSH version 2 and the common 1024-bit recommendation.

UniGlobe-Main-Switch(config-line)# exit

UniGlobe-Main-Switch(config)# line vty 0 15
UniGlobe-Main-Switch(config-line)# transport input ssh
Concept note: the transport input command (SSH only, Telnet only or both)

Each transport input line is a complete command on the VTY lines. It decides which remote protocols the switch accepts. The last command you enter replaces the previous one, so you can switch between the modes during the lab.

Command (under line vty 0 15)Allowedssh -l admin 192.168.1.10telnet 192.168.1.10
transport input sshSSH onlyWorksRefused
transport input telnetTelnet onlyRefusedWorks
transport input telnet sshBothWorksWorks
transport input noneNo remote accessRefusedRefused
  • Test each mode from Laptop0 and record the result in the table above.
  • Change the mode from the console (PC0), not from the remote session you are using, or you can lock yourself out.
  • The SSH lines in the configuration (domain name, RSA key, local user) stay in place whichever mode you choose. Only transport input changes what is accepted.
Concept notes: login local, privilege 15 and password types
  • login local and the line password: with login local the switch checks the username and password in the local database. The line's own password UniGlobe2026 is not used, so it is harmless but redundant. Use plain login if you want a line-only password.
  • Telnet with login local: Telnet users are also asked for a username and password, but both still cross the network in clear text.
  • Privilege 15: a user created with privilege 15 logs in straight to the # prompt. Without it the user lands at > and must type enable.
  • Type 7 vs type 5: service password-encryption gives type 7 (reversible, used for line passwords). enable secret and username ... secret are stored as type 5 (MD5 hash). They use the same hash here because the password and salt are the same.

  • The captured config shows transport input ssh (SSH only) and username admin secret without privilege 15. If yours matches, SSH users arrive at the > prompt and must type enable. Add privilege 15 to the username to land directly at #.

Troubleshooting
  • Cannot ping the switch: Vlan1 is shut down, the mask is wrong, or the host port was shut down.
  • SSH refused: RSA keys not generated, no domain name, or the VTY lines do not allow SSH.
  • Telnet refused: transport input ssh is set, which is the intended secure state.
  • "Login invalid": the user admin does not exist or the password is wrong. Passwords are case-sensitive.
  • Lands at > instead of #: the user has no privilege 15. Type enable.
