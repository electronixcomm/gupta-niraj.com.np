7.1

Redundancy issues in switched networks

Redundant physical links between switches protect the network from a single link or switch failure. In a mobile operator's aggregation network this matters a great deal: if the one cable between a hub site and the core is cut, every eNodeB, NodeB and BTS behind it drops off air. So designers always build at least two paths.

The catch is that Ethernet frames have no TTL (Time To Live) field. An IP packet that loops is discarded after its TTL reaches zero, and routing protocols such as RIP, EIGRP and OSPF prevent loops at Layer 3. A Layer 2 frame that loops circulates forever. STP is the Layer 2 mechanism that prevents loops.

Problems caused by a Layer 2 loop

ProblemWhat happens
Broadcast stormBroadcasts, multicasts and unknown unicasts (frames whose destination is not in the CAM table) are flooded out every port and keep circling. Link load and switch CPU climb within seconds. If the loop is confined to one VLAN, only ports in that VLAN and the trunks carrying it suffer.
Multiple frame copiesThe destination receives the same unicast frame several times. With more than one loop, every switch copies each frame out all ports again, so traffic multiplies.
MAC table instability (thrashing)The same source MAC arrives on different ports, so the switch keeps re-learning (flapping) where the host is. It no longer knows where any host really lives.
Device unresponsivenessWith links saturated and CPUs near 100 %, switches stop answering console and SSH sessions, which makes troubleshooting almost impossible.

Two ways STP itself can fail

1. A port blocks when it should forward. That segment becomes unusable, but the rest of the network keeps working, much like a failed routing protocol on one router.

2. A blocked port starts forwarding. This is the dangerous case. Every port lights up blinking amber/green, and the four problems above hit the whole network.

Recovering from a loopSystematically remove redundant links one by one until the storm stops and the switches recover. Then put the redundant links back one at a time while monitoring, so you find the failing port or switch. Keep a back-out plan ready in case it reoccurs.
7.2

Spanning Tree Protocol operation and root bridge election

STP (IEEE 802.1D, originally developed by DEC) uses the Spanning Tree Algorithm (STA) to build a topology database, elect a root bridge, and then block redundant ports so that exactly one active path exists between any two switches. Frames travel only on STP-chosen links. Switches exchange BPDUs (Bridge Protocol Data Units) every 2 seconds (the hello time) out of all active ports; the bridge ID is carried inside each BPDU.

Key terms

TermMeaning
Bridge ID (BID)8 bytes: 2-byte bridge priority (default 32768) + 6-byte base MAC address. The lowest BID is best.
Root bridgeThe switch with the lowest BID. It is the reference point; all its ports are designated (forwarding). It never has a root port.
Non-root bridgeEvery other switch. Each must build a single path to the root.
Port costValue set by link bandwidth (see table below).
Path costSum of port costs along a path to the root. Each possible path is evaluated separately.
Root port (RP)On each non-root switch, the one port with the lowest path cost to the root. Exactly one per non-root switch.
Designated port (DP)The single forwarding port on each segment: the one with the best cost to the root for that segment.
Non-designated portWhatever is left after RPs and DPs are chosen. Placed in blocking (802.1D) or discarding (802.1w).
Forwarding portForwards frames; always either a root port or a designated port.
Blocked portDrops all data frames and never transmits data, but still listens to BPDUs.
Alternate port (RSTP)Blocked port that offers an alternative path to the root through a different switch, which holds the designated port on that segment.
Backup port (RSTP)Blocked port connected to a segment where another port on the same switch is the designated port.

Bridge ID layout

The three-step STP process

  1. Elect the root bridge. Lowest priority wins; on a tie, the lowest MAC address. To compare MACs, read left to right until one digit is smaller: 0000.0cab.3274 beats 0000.0cf6.9370.
  2. Choose one root port on each non-root switch. Lowest accumulated path cost to the root. Tie-breakers: lowest sender bridge ID, then lowest sender port priority, then lowest sender port number.
  3. Choose one designated port per segment. In order: (1) lowest accumulated path cost to the root from the switch on that segment; (2) if tied, lowest bridge ID; (3) port priority (default 128 in IOS output as 128.x; Lammle's text quotes 32), which you can lower to force a port; (4) lowest port number, so Fa0/1 beats Fa0/2. Every remaining port blocks.
Worked exampleS1 (lowest MAC) is root. S3 reaches it directly over Gigabit (cost 4); via S2 the cost would be 4 + 4 = 8, so S3's root port is the direct link. Same for S2. On the S2–S3 segment both switches have root path cost 4, so the lower bridge ID wins: S3 (000A.41D5.7937) beats S2 (0030.F222.2794), S3's port is designated and S2's port blocks.

Extended system ID

PVST+ needs a different BID per VLAN, so the 16-bit priority field is split into a 4-bit priority and a 12-bit sys-id-ext carrying the VLAN ID. Priority therefore moves in steps of 4096 (0, 4096 … 61440).

RSTP designated-port rule in practiceLammle's RSTP example 2: SC (priority 28672) is root. SA has a 10 Gb/s link to SC (cost 2). On the SA–SD segment, SD has the lower MAC, but SA's accumulated cost (2) is lower than SD's (4), so SA's port is designated and SD's port discards. Path cost is checked before bridge ID.
Telecom anglePVST+/Rapid PVST+ lets an operator make the core switch root for 4G VLANs and a hub switch root for 2G/3G VLANs, so both uplinks carry traffic instead of one sitting idle. The lab uses exactly this design.

Configuring the root bridge, PortFast and BPDU Guard

Choosing the root yourself

Left alone, the oldest switch (lowest MAC) often becomes root, which can force traffic through a weak box. Always set the priority on the switch you want as root.

S2(config)# spanning-tree vlan 2 priority ?
  <0-61440>  bridge priority in increments of 4096
S2(config)# spanning-tree vlan 2 priority 16384      ! effective 16384 + 2 = 16386
S2(config)# spanning-tree vlan 3 root primary        ! sets 24576, or lower than current root
S3(config)# spanning-tree vlan 3 root secondary      ! sets 28672
S2(config)# spanning-tree mode rapid-pvst            ! global: Rapid PVST+ for all VLANs
S2# show spanning-tree vlan 2
S2# show spanning-tree summary                       ! "Root bridge for: VLAN0002 VLAN0003"
  • Priority 0 makes a switch root unless another switch also has 0 and a lower MAC. Never set every switch to 0.
  • If both primary and secondary root fail, the switch with the next-best BID takes over.
  • To be root for every VLAN, set the priority for each VLAN.

PortFast

PortFast (a Cisco extension to 802.1D) moves an access port straight from blocking to forwarding, skipping the ~50 s wait. Use it only on ports that connect to a single end device (PC, server, router, or a cell-site baseband unit) and never to a switch or hub. IOS warns you when you enable it. spanning-tree portfast default enables it on all non-trunking ports; spanning-tree portfast trunk exists for a trunk to a server or router.

BPDU Guard

If a PortFast port receives a BPDU, BPDU Guard puts it into err-disabled (shut down), so nobody can extend the network with a rogue switch. Configure it on access-layer switches where users or devices connect. Recover with shutdown / no shutdown after removing the cause, or automatically with errdisable recovery cause bpduguard.

7.3

Switch port security

Port security limits which MAC addresses may send frames into an access port. It protects against MAC flooding attacks, rogue devices and unauthorised access, for example a laptop plugged into a cell-site switch port meant only for an eNodeB. The port must be statically set to access (or trunk); a port in dynamic (DTP) mode cannot use port security.

How secure MAC addresses are learned

TypeHow it is addedWhere it is storedSurvives reload?
Static secureTyped: switchport port-security mac-address 00d0.ba12.3401Address table + running configYes, after copy run start
Dynamic secure (default)Learned from trafficAddress table onlyNo
Sticky secureLearned dynamically, then written as mac-address sticky <mac>Address table + running configYes, after copy run start

Aging

Secure addresses can expire so the maximum frees up. switchport port-security aging time <minutes> sets the timer. aging type absolute removes the address after that time regardless of activity; aging type inactivity removes it only after it has been idle for that time. Statically configured addresses do not age unless you add aging static. Aging is most useful for dynamically learned addresses; on many Catalyst platforms sticky addresses are not aged, so the lab combines a static address with dynamic learning when an entry must expire.

Violation modes

A violation occurs when a new MAC would exceed the maximum (default 1), or when a secure MAC learned on one secure port appears on another secure port in the same VLAN.

7.4

      
Link aggregation with EtherChannel

      

        
When you cable several links between two switches, STP blocks all but one, and routing protocols may treat each link as a separate adjacency. EtherChannel (Cisco's term for port channelling) bundles 2 to 8 active ports into one logical port-channel interface. STP and routing protocols then see a single link, so nothing blocks inside the bundle and only one routing adjacency forms.

        
Benefits: more bandwidth, load sharing across members (the Load column in show etherchannel port-channel is a hex value used to choose a member for each flow, not a traffic figure), and resilience: a failed member does not trigger STP reconvergence.

      

      
Member ports must matchSpeed, duplex, VLAN configuration and trunk mode, native VLAN and allowed VLAN list. You cannot mix interface types or settings in one bundle. Settings made under interface port-channel are inherited by the member interfaces.

VLAN, trunk and VTP recap

      

        

          
VLANs and trunks

          
    
            
  • VLAN 1 is the default and default native VLAN; it cannot be renamed or deleted. VLANs 1002–1005 are also reserved. Change the native VLAN to an unused VLAN for security.
    • 
            
  • switchport mode access = permanent non-trunk. dynamic auto trunks only if the neighbour is trunk/desirable. dynamic desirable actively tries to trunk. trunk = permanent trunk. switchport nonegotiate stops DTP.
    • 
            
  • The 2960 supports only 802.1Q; on a 3560 enter switchport trunk encapsulation dot1q before switchport mode trunk.
    • 
            
  • All VLANs 1–4094 are allowed on a trunk by default. Edit with switchport trunk allowed vlan add | remove | all | except.
    • 
            
  • show vlan lists only access ports; trunks appear in show interfaces trunk.
    • 
            
  • A voice VLAN (switchport voice vlan n) lets one access port carry an IP phone's voice VLAN plus the PC's data VLAN.
    • 
          

        

        

          
VTP (VLAN Trunking Protocol)

          
    
            
  • Cisco protocol that propagates VLAN add/delete/rename across a domain over trunk links only. Normal-range VLANs 1–1005 only; extended VLANs 1006–4094 require transparent mode.
    • 
            
  • Server (default): creates/changes VLANs, saves to NVRAM. Client: cannot create VLANs, learns from servers, does not save to NVRAM. Transparent: keeps its own local VLAN database and forwards VTP adverts without applying them.
    • 
            
  • To share VLANs: same version, same domain name, a server present, same password if used.
    • 
            
  • A higher configuration revision always wins. A new switch with a higher revision can wipe every VLAN in the domain. Reset by changing the domain name and back, or set it to client/transparent before connecting.
    • 
            
  • VTP pruning (off by default; VLANs 2–1001 eligible, VLAN 1 never) stops flooding a VLAN down trunks to switches that have no ports in it. VTPv2 adds Token Ring, unrecognised TLV support, version-independent transparent mode and consistency checks.
    • 
          

        

      

      
Operator practiceMany mobile operators run their RAN aggregation switches in VTP transparent mode, so a mis-wired switch cannot delete the 4G, 3G and 2G service VLANs network-wide. The lab does the same.

Why use VLAN 999 as native instead of VLAN 1 or VLAN 99?Untagged frames on a trunk land in the native VLAN. Using an unused VLAN with no hosts and no SVI blocks VLAN-hopping (double-tagging) attacks and stops management traffic from being exposed untagged. VLAN 1 is the default everywhere, so it is the first thing an attacker tries.

      
Why is VLAN 310 listed on AGG-SW3 even though no 3G equipment connects there?In transparent mode each switch keeps its own VLAN database. SW3 is a transit switch for VLAN 310 when its traffic uses the SW2–SW3 path, and a VLAN that does not exist locally is not forwarded across a trunk.

Q: What is CORE-SW1's effective priority for VLAN 110 after root primary?24576 + 110 = 24686. root primary sets 24576 when the current root has the default 32768; if another switch were already below 24576 it would set 4096 less than that switch.

      
Q: Why does AGG-SW2 not choose the gigabit path to reach the 4G root?Via SW3 the path is Gi (4) + SW3–SW1 Fa (19) = 23, which is worse than its direct Fa link (19). STP picks lowest total cost, not the fastest first hop.

      
Q: X2 traffic between eNB-01 (SW3) and eNB-02 (SW2) is in VLAN 130. Which path does it take after Part C?SW3 → CORE-SW1 → SW2, because SW3's Gi ports are blocked for VLAN 130. The X2 traffic is carried through the core. A designer could make SW2 root for VLAN 130 to keep X2 local, at the cost of S1 paths. That is the trade-off PVST+ lets you choose.

Q: When would you choose restrict over shutdown?When availability matters more than isolation: on a port carrying live subscriber traffic, restrict keeps the legitimate eNodeB in service while dropping and logging the intruder. Shutdown suits ports where any intrusion is serious, such as O&M, because it cuts the port completely.

      
Q: What happens to dynamic secure MACs after a reload? And sticky ones that were not saved?Both are lost. Dynamic entries live only in the address table; sticky entries are in the running config and survive only after copy run start.
