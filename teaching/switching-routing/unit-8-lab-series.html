Unit 8 · Lab series · 6 short labs · about 4 hours

Branch office to HQ to the internet

A company has a branch office and a head office (HQ), joined by a leased serial line. HQ also has a serial link to an ISP, which leads to the internet. You will bring up the WAN links (HDLC and PPP), filter traffic with ACLs, and use NAT so private PCs can reach an internet web server while HQ's own web server is published to the internet.

3 routers (1941 + HWIC-2T) 2 switches (2960, no config) 3 PCs · 2 Servers Static routing only

Build in Packet Tracer (15 min)
  1. Place three 1941 routers. For each: Physical tab → switch power off → drag HWIC-2T into a slot → power on. This adds S0/0/0 and S0/0/1.
  2. Connect serial links with Serial DCE cable: click HQ first for the BRANCH–HQ link and ISP first for the HQ–ISP link. The first-clicked end becomes DCE (clock icon).
  3. Use copper straight-through for PC/server ↔ switch ↔ router, and copper cross-over for INTERNET-SRV ↔ ISP G0/0.
  4. Set each PC/server's IP, mask and gateway (Desktop → IP Configuration). Servers already run HTTP.

Lab 2 · 35 min

PPP with CHAP authentication

8.1 · 8.2
TASK

Authenticate the branch link

Change the BRANCH–HQ link to PPP and require CHAP so a rogue router cannot connect. Leave the HQ–ISP link on HDLC.

Part A · Encapsulation mismatch (observe first)

  1. On BRANCH only: interface s0/0/0 → encapsulation ppp.
  2. show interfaces s0/0/0 on both routers: up, line protocol down. One side speaks PPP, the other HDLC. PC-B1 can no longer reach HQ.

Part B · PPP + CHAP on both ends

BRANCH(config)# username HQ password Cisco123
BRANCH(config)# interface s0/0/0
BRANCH(config-if)# encapsulation ppp
BRANCH(config-if)# ppp authentication chap
HQ(config)# username BRANCH password Cisco123
HQ(config)# interface s0/0/0
HQ(config-if)# encapsulation ppp
HQ(config-if)# ppp authentication chap
HQ# show interfaces serial 0/0/0
Serial0/0/0 is up, line protocol is up
  Encapsulation PPP, LCP Open
  Open: IPCP, CDPCP
HQ# show interfaces serial 0/0/1      ! still Encapsulation HDLC

Part C · Wrong password test

  1. On HQ: username BRANCH password wrong123. Then shutdown / no shutdown on S0/0/0.
  2. Run debug ppp authentication on HQ. The link stays up / down and CHAP fails.
  3. Restore username BRANCH password Cisco123, then undebug all. Ping SRV-HQ from PC-B1 again.
Optional: PAP instead of CHAP 
BRANCH(config)# interface s0/0/0
BRANCH(config-if)# ppp authentication pap
BRANCH(config-if)# ppp pap sent-username BRANCH password Cisco123
! HQ: ppp authentication pap + ppp pap sent-username HQ password Cisco123

In Simulation mode, click a PAP packet: the password is visible in clear text. Switch back to CHAP afterwards.

Lab 3 · 35 min

Standard ACLs

8.2
TASK

Keep the guest out of HQ and lock down router access

(1) PC-B2 (guest) must not reach the HQ LAN, but may still use the internet later. (2) Only PC-HQ may Telnet to the HQ router.

Part A · Block the guest (placed near the destination)

HQ(config)# ip access-list standard NO-GUEST
HQ(config-std-nacl)# remark Guest PC may not enter HQ LAN
HQ(config-std-nacl)# deny host 192.168.10.20
HQ(config-std-nacl)# permit any
HQ(config-std-nacl)# exit
HQ(config)# interface g0/0
HQ(config-if)# ip access-group NO-GUEST out

Why on HQ G0/0 out? A standard ACL only sees the source. Placed at BRANCH, it would block the guest from everything, including the internet. Placed at the HQ LAN exit, it blocks only the HQ LAN.

TestExpected
PC-B2 ping 192.168.20.100Fails (Destination host unreachable)
PC-B1 ping 192.168.20.100Success
HQ# show access-listsMatch counters increase on each line

Part B · Restrict Telnet to the router

HQ(config)# enable secret Class123
HQ(config)# line vty 0 4
HQ(config-line)# password Telnet123
HQ(config-line)# login
HQ(config-line)# exit
HQ(config)# access-list 5 permit host 192.168.20.10
HQ(config)# line vty 0 4
HQ(config-line)# access-class 5 in

Test from each PC's Command Prompt: telnet 192.168.20.1. PC-HQ gets the password prompt; PC-B1 gets Connection refused.

Lab 4 · 35 min

Extended ACL

8.2
TASK

Branch may use only the HQ web server

Branch PCs may browse SRV-HQ (HTTP) and ping it for testing. All other traffic from the branch to the HQ LAN is denied. Internet traffic stays allowed. Filter at the branch so blocked packets never use the WAN link.
BRANCH(config)# ip access-list extended BRANCH-IN
BRANCH(config-ext-nacl)# remark Branch to HQ: web server only
BRANCH(config-ext-nacl)# permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq www
BRANCH(config-ext-nacl)# permit icmp 192.168.10.0 0.0.0.255 host 192.168.20.100 echo
BRANCH(config-ext-nacl)# deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
BRANCH(config-ext-nacl)# permit ip any any
BRANCH(config-ext-nacl)# exit
BRANCH(config)# interface g0/0
BRANCH(config-if)# ip access-group BRANCH-IN in

Lab 5 · 40 min

NAT for internet access: PAT and static NAT

8.3
TASK

Get the private network onto the internet

All branch and HQ PCs must share HQ's public address (PAT). SRV-HQ must be reachable from the internet at 209.165.200.229 (static NAT).
HQ(config)# interface g0/0
HQ(config-if)# ip nat inside
HQ(config-if)# interface s0/0/0
HQ(config-if)# ip nat inside             ! branch traffic enters HQ here
HQ(config-if)# interface s0/0/1
HQ(config-if)# ip nat outside
HQ(config-if)# exit
HQ(config)# ip nat inside source static 192.168.20.100 209.165.200.229
HQ(config)# access-list 1 permit 192.168.10.0 0.0.0.255
HQ(config)# access-list 1 permit 192.168.20.0 0.0.0.255
HQ(config)# ip nat inside source list 1 interface s0/0/1 overload

Lab 6 · 45 min

Secure the WAN edge, then troubleshoot

8.3

Part A · Harden HQ (10 min)

HQ(config)# service password-encryption
HQ(config)# interface s0/0/1
HQ(config-if)# no cdp enable                 ! do not advertise to the ISP
HQ(config-if)# exit
HQ(config)# ip access-list extended OUTSIDE-IN
HQ(config-ext-nacl)# remark Anti-spoofing: no private sources from the internet
HQ(config-ext-nacl)# deny ip 10.0.0.0 0.255.255.255 any
HQ(config-ext-nacl)# deny ip 172.16.0.0 0.15.255.255 any
HQ(config-ext-nacl)# deny ip 192.168.0.0 0.0.255.255 any
HQ(config-ext-nacl)# permit ip any any
HQ(config-ext-nacl)# exit
HQ(config)# interface s0/0/1
HQ(config-if)# ip access-group OUTSIDE-IN in
HQ(config-if)# end
HQ# copy running-config startup-config

Re-test Lab 5: internet access and the published server still work. show running-config now shows passwords as type 7 strings.

Part B · Trouble tickets

Work in pairs: one student secretly injects a fault, the other uses only show and debug commands to find it. Log: symptom → command → finding → fix.
