Lab 3B: VLAN Creation, Trunk Configuration and Router-on-a-Stick

Packet Tracer · 2960-24TT switch and PT8200 router · Problem statement with solution

1 Intro to PT/GNS32 Switch setup3 VLANs & router-on-a-stick4 Static & default routes5 RIPv26 OSPF / EIGRP7 STP, port security, EtherChannel8 PPP/HDLC, ACL, NAT

1. Scenario

A company has two departments that must be separated at layer 2 but still able to talk to each other: the VLAN 10 users and the VLAN 20 users. A third VLAN holds the DHCP server. Only one physical link joins the switch to the router, so you will carry all three VLANs over a single trunk and let the router route between them using subinterfaces (router-on-a-stick). The router must also relay DHCP requests to the server, which lives in a different subnet.

Learning objectives

  • Create VLANs and assign access ports.
  • Configure an 802.1Q trunk that allows only the needed VLANs.
  • Configure router subinterfaces with dot1Q encapsulation for inter-VLAN routing.
  • Use a DHCP relay (ip helper-address) and a central DHCP server.

Part 1Build and cable the network

  1. Place Switch1 (2960-24TT), Router0 (PT8200), Laptop0 to Laptop3 and Server1.
  2. Connect Laptop0/1 to Fa0/1–Fa0/2, Laptop2/3 to Fa0/11–Fa0/12 and Server1 to Fa0/21 with straight-through cables.
  3. Connect Switch1 Gi0/1 to Router0 G0/0/0 with a copper cable.
Checkpoint: All links turn green. The router link may stay down until you issue no shutdown in Part 4.

Part 2Create VLANs and assign access ports

  1. On Switch1 create VLANs 10, 20 and 100 (give them names).
  2. Put Fa0/1–10 in VLAN 10, Fa0/11–20 in VLAN 20 and Fa0/21 in VLAN 100, all as access ports.
Checkpoint: show vlan brief lists each VLAN with the correct ports. Unused ports Fa0/22–24 stay in VLAN 1.

Part 3Configure the trunk

  1. Make Gi0/1 on Switch1 an 802.1Q trunk toward the router.
  2. Allow only VLANs 10, 20 and 100 on the trunk.
Checkpoint: show interfaces trunk shows Gi0/1 in trunking mode with allowed VLANs 10,20,100.
Show solution
interface GigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,100

Limiting the allowed list keeps other VLANs off the link. In Packet Tracer the 2960 only supports 802.1Q, so no trunk encapsulation command is needed.

Part 4Router-on-a-stick and DHCP relay

  1. Bring up Router0 G0/0/0 without an IP address.
  2. Create subinterfaces .10, .20 and .100 with the matching dot1Q VLAN IDs and gateway addresses.
  3. Add ip helper-address 172.16.100.2 on the subinterfaces so DHCP broadcasts reach Server1.
Checkpoint: show ip interface brief shows the three subinterfaces up/up, and show ip route lists connected routes for 192.168.1.0/24, 192.168.2.0/24 and 172.16.100.0/30.
Show solution
enable
configure terminal
hostname Router0
interface GigabitEthernet0/0/0

interface GigabitEthernet0/0/0.10
 encapsulation dot1Q 10
 ip address 192.168.1.1 255.255.255.0
 ip helper-address 172.16.100.2
interface GigabitEthernet0/0/0.20
 encapsulation dot1Q 20
 ip address 192.168.2.1 255.255.255.0
 ip helper-address 172.16.100.2
interface GigabitEthernet0/0/0.100
 encapsulation dot1Q 100
 ip address 172.16.100.1 255.255.255.252
 ip helper-address 172.16.100.2
end

Each subinterface is the default gateway for one VLAN. The router tags and untags frames with the VLAN ID given in encapsulation dot1Q. The helper address on the .100 subinterface is not strictly needed (the server is already on that subnet) but is harmless.

Concept note: why ip helper-address is needed

What it does: it makes the router forward DHCP requests that it would normally drop. The command goes on the interface that receives the clients' requests.

Why it is needed here: a laptop set to DHCP has no address and does not know where the server is, so its DHCPDISCOVER is a broadcast (255.255.255.255). Routers do not forward broadcasts, so the request would stop at the VLAN 10 or VLAN 20 subinterface. Server1 is in a different subnet (172.16.100.0/30), so without the helper it is never reached and the laptop falls back to an APIPA address (169.254.x.x).

StepWhat happens
1Laptop0 (VLAN 10) broadcasts a DHCPDISCOVER.
2Router0 receives it on G0/0/0.10 and converts the broadcast into a unicast to 172.16.100.2.
3The router writes its own subinterface address (192.168.1.1) into the packet's giaddr (relay agent) field.
4Server1 reads giaddr, sees it belongs to 192.168.1.0/24 and offers an address from VLAN10_Pool.
5The reply goes back to 192.168.1.1 and the router passes it to Laptop0. The request and acknowledgment follow the same relayed path.
Notes
  • Put it on the client-facing interfaces (G0/0/0.10 and G0/0/0.20). On .100 it does no harm but is not required.
  • Server1 needs a default gateway (172.16.100.1), because its replies go to giaddr, which is on another subnet.
  • Each subnet needs its own pool. The server chooses the pool from giaddr, so the pool subnet must match the subinterface subnet.
  • By default the helper also relays other UDP broadcasts (TFTP 69, DNS 53, TACACS 49, time 37, NetBIOS 137/138). Use no ip forward-protocol udp <port> to stop any of them.
  • Alternatives: a DHCP server in every VLAN, or the router acting as the DHCP server with ip dhcp pool. A central server with a relay is easier to manage.

Part 5Configure Server1 and its DHCP service

  1. Set Server1's IP address, mask and default gateway.
  2. Enable the DHCP service and create one pool for VLAN 10 and one for VLAN 20. The gateway in each pool is the router subinterface.
Checkpoint: Server1 pings 172.16.100.1. The DHCP page lists the two pools with service On.

Part 6Verify and test inter-VLAN routing

  1. Set Laptop0 to Laptop3 to DHCP (Config > FastEthernet0 or Desktop > IP Configuration).
  2. Record the address, mask and gateway each laptop receives.
  3. Ping between laptops in the same VLAN, then between VLANs (for example Laptop0 to Laptop2), and ping Server1.
  4. Run tracert from Laptop0 to Laptop2.
Checkpoint: Laptops get addresses from the right pool (192.168.1.x for VLAN 10, 192.168.2.x for VLAN 20). Same-VLAN and cross-VLAN pings succeed. The traceroute shows 192.168.1.1 as the first hop, then the destination.

  • The first laptop in each VLAN normally gets .10 (the pool start address), the second gets .11.
  • No DHCP address: check the trunk allows the VLAN, the subinterface has the right dot1Q ID, the helper-address points to 172.16.100.2 and Server1 has its gateway set.
  • Cross-VLAN ping fails: confirm no shutdown on the parent G0/0/0 and that each laptop's gateway is its subinterface address.
  • Link up but nothing passes: make sure the switch port facing the router is a trunk, not an access port.
