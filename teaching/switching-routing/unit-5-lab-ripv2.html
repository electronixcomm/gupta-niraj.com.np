Lab Series 5: Configuring RIPv2, Verifying Updates & Debugging RIP Routing

Packet Tracer lab series (6 labs, build on each other) · Routers: Cisco 2911 · Nepal enterprise network (Kathmandu HQ, Pokhara, Biratnagar, Butwal)

1. Scenario

A company has its headquarters in Kathmandu and three branch offices. HQ-R1 connects to the Internet through ISP-R, with a primary Gigabit link and a backup serial link. HQ-R2 is the core router linking to HQ-R1, BR-A (Pokhara) and BR-B (Biratnagar) over a Gigabit link and a serial link respectively. BR-A and BR-B have a direct link that should be the preferred path between branches. BR-C (Butwal) is a small stub depot behind BR-B that cannot run RIP.

You are the network engineer. Over six short labs you will build the network, configure RIPv2 and static routing, and finish with every host able to reach every other host and the Internet server.

3. The lab series

Complete the labs in order; each builds on the previous one. Every lab has a checkpoint to confirm it works and a collapsible solution.

  1. Build, cable and address the network
  2. Configure RIPv2
  3. Secure the LANs with passive interfaces
  4. Internet access with a floating backup
  5. Butwal stub network
  6. ISP return routes and full connectivity

Get every link up before any routing is configured.

  2. Name the routers and assign every interface address from the table. Use clock rate 64000 on each DCE end.
  3. Configure the six end devices with their IP, mask and the correct default gateway (fill in the "?" in the host table).

Lab 5.2Configure RIPv2

Share the internal 10.x and 172.16.x networks between the four RIP routers.

  1. On HQ-R1, HQ-R2, BR-A and BR-B enable RIP version 2 and disable automatic summarisation.
  2. Advertise only the classful networks each router needs. ISP-R and BR-C must not run RIP.
Checkpoint: show ip protocols shows RIPv2 with auto-summary off. show ip route rip on HQ-R2 lists the branch LANs and 172.16.20.0/24.
Show solution
HQ-R1
router rip
 version 2
 no auto-summary
 network 10.0.0.0
 network 172.16.0.0
HQ-R2
router rip
 version 2
 no auto-summary
 network 10.0.0.0
BR-A
router rip
 version 2
 no auto-summary
 network 10.0.0.0
 network 172.16.0.0
BR-B
router rip
 version 2
 no auto-summary
 network 10.0.0.0

Why no auto-summary: 172.16.20.0/24 (HQ-R1) and 172.16.50.0/24 (BR-A) are separated by 10.x networks, so summarising to 172.16.0.0/16 would break routing.

Lab 5.3Secure the LANs with passive interfaces

Stop RIP updates reaching places where no router listens.

  1. Make every user/server LAN interface passive (HQ Servers, HQ Users, Branch A, Branch B).
  2. BR-B must also send no updates toward the Butwal depot.
  3. Never make a router-to-router RIP link passive.
Checkpoint: show ip protocols lists the passive interfaces on each router, and RIP routes are still exchanged.
Show solution
HQ-R1
router rip
 passive-interface GigabitEthernet0/2
HQ-R2
router rip
 passive-interface GigabitEthernet0/1
BR-A
router rip
 passive-interface GigabitEthernet0/1
BR-B
router rip
 passive-interface GigabitEthernet0/0
 passive-interface GigabitEthernet0/2

Lab 5.4Internet access with a floating backup

HQ-R1 reaches the Internet over the primary circuit and fails over to the serial link.

  1. Give HQ-R1 a default route through ISP-R G0/0.
  2. Add a second default route over the serial link that is used only if the primary fails.
  3. Make HQ-R1 pass its default route to every other RIP router.
Checkpoint: HQ-R1 shows S* 0.0.0.0/0 via 172.31.0.1; HQ-R2, BR-A and BR-B show R* 0.0.0.0/0 (AD 120).
Show solution
HQ-R1
ip route 0.0.0.0 0.0.0.0 172.31.0.1
ip route 0.0.0.0 0.0.0.0 172.31.0.5 200
!
router rip
 default-information originate

Static AD is 1, RIP is 120 and the floating backup is 200, so the backup stays out of the table until the primary route disappears.

Lab 5.5Butwal stub network

BR-C cannot run RIP, so connect it with static routes.

  1. Give BR-C a default route toward BR-B.
  2. Give BR-B a static route to the Butwal LAN.
  3. Make BR-B advertise that route into RIP without sending RIP towards BR-C.
Checkpoint: show ip route on HQ-R2, BR-A and BR-B shows 192.168.30.0/24 learned via RIP (or static on BR-B). PC-C can ping PC-B.
Show solution
BR-C
ip route 0.0.0.0 0.0.0.0 10.0.4.1
BR-B
ip route 192.168.30.0 255.255.255.0 10.0.4.2
!
router rip
 redistribute static

Lab 5.6ISP return routes and full connectivity

The ISP does no NAT, so it needs a way back into the company.

  1. On ISP-R add routes to 10.0.0.0/8, 172.16.0.0/16 and 192.168.30.0/24 via HQ-R1 G0/0.
  2. Add backup versions through the serial link, used only if the primary fails.
  3. Test end to end, including a failover by shutting ISP-R G0/0.
Checkpoint: Every PC and server pings every other one. After shutting ISP-R G0/0, HQ-R1 shows S* 0.0.0.0/0 [200/0] via 172.31.0.5 and PC-HQ still reaches Internet-Server. Restore the link afterwards.
Show solution
ISP-R
ip route 10.0.0.0 255.0.0.0 172.31.0.2
ip route 172.16.0.0 255.255.0.0 172.31.0.2
ip route 192.168.30.0 255.255.255.0 172.31.0.2
