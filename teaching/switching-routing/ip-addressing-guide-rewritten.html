NETWORK DESIGN REFERENCE · REVIEW CLASS

IP Addressing: From Classes to CIDR, LPM and VLSM (Review Class)

In this guide we study three things: subnetting (carving one block into smaller networks), supernetting, i.e. summarization (merging many networks into one route), and how a router actually works in two steps: first it builds its routing table (administrative distance, then metric), then it forwards each packet (longest-prefix match). Three Nepali case studies and VLSM tie it together.

1The Problem Classes Created

An IPv4 address is 32 bits, written as four octets (192.168.1.10). Every address splits into a network ID (which network) and a host ID (which device). The whole story is about where that split falls.

Until 1993 the first bits of an address fixed the split, giving five classes:

Table 1 — The five classes (127.x.x.x is reserved for loopback)
ClassLeading bitsFirst octetDefault maskHosts / network
A01–126/816,777,214
B10128–191/1665,534
C110192–223/24254
D1110224–239Multicast
E1111240–255Experimental

To identify a class, read the first octet: 172.16.0.0 → 172 = 10101100 → leading bits 10 → Class B.

THE PROBLEM

The boundaries were rigid. A company needing 300 hosts could not get “a bit more than a Class C”; it received a whole Class B (65,534 addresses) and wasted over 65,000. Multiplied across the internet, this drained IPv4 space and bloated routing tables.

1.1The Fix: CIDR (RFC 1519, 1993)

Classless Inter-Domain Routing drops the classes. An explicit prefix length /n (anywhere from /0 to /32) marks the split, regardless of the first octet. That unlocks two opposite tools:

  • Subnetting borrows host bits to cut one network into smaller ones sized to real need.
  • Supernetting borrows network bits to merge contiguous networks into one advertised route.

2Reading a Prefix

A prefix and a mask say the same thing: every 1 in the mask is a network bit, every 0 a host bit. /26 = 11111111.11111111.11111111.11000000 = 255.255.255.192, leaving 6 host bits → 64 addresses, 62 usable.

  • Network address: all host bits 0. Names the block; never assigned.
  • Broadcast address: all host bits 1. Reaches every host; always the block’s last address.
  • Usable hosts: everything strictly between the two.

MASK SHORTCUT

Full octets are 255. In the partial octet take k = n mod 8 bits: 1→128, 2→192, 3→224, 4→240, 5→248, 6→252, 7→254; later octets are 0. Block size = 256 − mask octet. Example: /27 → 224 → block size 32.

2.1The Two Extremes

  • /0 matches everything. No bits are compared, so 0.0.0.0/0 catches every destination: the default route to the ISP, the firewall “any”, the default a core advertises to branches. It always loses to anything more specific.
  • /32 matches one host. No network ID, no broadcast. Used for loopbacks (stable router identity for OSPF/BGP), host routes that override a covering /24, tunnel endpoints, single-IP firewall rules, and RTBH (an ISP routes a DDoS victim’s /32 to Null0).

3Subnetting: Carving a Block

PROBLEM STATEMENT

Split 192.168.10.0/24 into /27 subnets. How many are there, how big is each, and what are their network, host-range and broadcast addresses?

3.1Two Sizing Formulas

Each extra bit doubles a count, so exact sizes come from log₂, rounded up (a fractional bit cannot exist).

FORMULA 1 — HOST BITS FOR H HOSTS

n = ⌈log₂(H + 2)⌉, then prefix = 32 − n. The “+2” covers the network and broadcast addresses. Check: 2ⁿ − 2 ≥ H.

FORMULA 2 — SUBNET BITS FOR N SUBNETS

s = ⌈log₂(N)⌉. Check: 2ˢ ≥ N.

3.2The Method

  1. Start from the parent. 192.168.10.0 is Class C → /24, 8 host bits.
  2. Count borrowed bits. New prefix − old = 27 − 24 = 3.
  3. Count subnets. 2³ = 8.
  4. Count hosts. 5 host bits → 32 addresses, 30 usable.
  5. Find block size. Mask octet 224 → 256 − 224 = 32.
  6. List subnets. Start at 0, keep adding 32: 0, 32, 64, 96, 128, 160, 192, 224. Next would be 256, which rolls into the next octet, so it is the stop signal, not a ninth subnet.
  7. Fill rows. Broadcast = next start − 1; usable = network + 1 to broadcast − 1.

#NetworkUsableBroadcast

2192.168.10.32.33 – .62.63
3192.168.10.64.65 – .94.95
4192.168.10.96.97 – .126.127

THE 256 RULE (SELF-CHECK)

In the octet where the split happens, subnets × block size = 256 (here 8 × 32). If it fails, a step is wrong. When borrowed bits spill into a second octet, apply it per octet: /8 → /18 borrows 10 bits, giving 4 × 64 in the third octet, repeated for 256 second-octet values = 1,024 subnets.

COMMON MISTAKES

32 is addresses, not hosts (30 usable). The last broadcast is .255 (224 + 31), not .225. Subnet zero is usable under classless rules; old classful rules discarded the first and last subnets (2ⁿ − 2).

4How a Router Picks the Path

PROBLEM STATEMENT

A router holds many overlapping routes, learned from several protocols. When a packet for 192.168.12.41 arrives, which route forwards it, and which routes are even allowed into the table?

Two separate decisions answer this: AD and metric build the table; longest-prefix match forwards each packet.

4.1Forwarding: Longest-Prefix Match (LPM)

  1. Read the destination from the packet.
  2. AND it with each route’s mask (not the route’s address). Full octets: 255 keeps, 0 clears. Partial octet: use binary.
  3. Compare with the route’s network address. Equal = match.
  4. Pick the longest matching prefix. Table order is irrelevant.

0.0.0.0/00.0.0.0Yes0
192.168.0.0/16192.168.0.0Yes16
192.168.12.0/24192.168.12.0Yes24
192.168.12.40/30192.168.12.40Yes30
192.168.12.64/26192.168.12.0No (≠ .64)–
/30:  41 = 00101001  AND 252 = 11111100  →  00101000 = 40  ✓ equals .40
/26:  41 = 00101001  AND 192 = 11000000  →  00000000 =  0  ✗ not .64
Longest match = /30 → forwarded to the 192.168.12.40/30 next hop

Specific beats general, even for one host: with routes 0/0, 10.10.0.0/16, 10.10.20.0/24 and 10.10.20.99/32, the address .99 follows the /32 (firewall), .45 follows the /24 (server VLAN), and 8.8.8.8 falls to the default.

COMMON TRAP

Eyeballing whole octets stops at 24 bits and misses matches hidden in the third or fourth octet. Always AND with the mask. Example: 10.50.130.5 vs 10.50.64.0/18: 130 AND 192 = 128 ≠ 64, no match.

4.2Building the Table: AD, then Metric

The same prefix may be offered by several sources (static, OSPF, RIP, BGP…). Each protocol measures “best” differently, so metrics from different protocols cannot be compared. Administrative distance (AD) ranks the sources by trustworthiness; the metric (lower is better) ranks routes within one source.

Table 4 — Typical Cisco AD and metric by source

The router keeps one selection per prefix:

  1. Group by identical prefix and length. Different lengths are different destinations; all are installed.
  2. Lowest AD wins. Metrics are not compared across sources.
  3. Equal AD → lowest metric wins.
  4. Equal metric too → ECMP. Several next hops share the load.
  5. Losers wait in reserve and return if the winner fails. A floating static (AD set above the dynamic protocol, e.g. 200) works exactly this way.

Example: for 10.10.20.0/24, static (AD 1), OSPF cost 10 and 25 (AD 110) and RIP (AD 120) all compete. Static is installed; if it vanishes, OSPF cost 10 takes over, then cost 25, then RIP.

KEY POINT

AD decides which source supplies a prefix; LPM decides which prefix forwards the packet. An iBGP /32 (AD 200) still beats an OSPF /24 (AD 110) at forwarding time, because AD never enters the forwarding decision.

5Summarization: Many Routes, One Advertisement

One postal code for a whole district: the core needs a single entry, not one per street.

PROBLEM STATEMENT

A backbone router holds four separate routes, 192.168.16.0/24 to 192.168.19.0/24. Can one route replace them without claiming any address that is not theirs?

Summarization (supernetting) collapses several specific routes into one. It shrinks routing tables (saving memory and CPU), hides flapping of individual subnets from the rest of the network, and cuts routing updates. It works only when the networks fit together exactly. The shared leading bits give the answer:

3rd octet:  16 = 00010000   17 = 00010001   18 = 00010010   19 = 00010011
First 6 bits identical → 8 + 8 + 6 = 22   → 192.168.16.0/22 (255.255.252.0)

5.1The Rule

For networks of equal size (prefix p, block size b in the octet where they differ), work in ascending order:

  1. Check contiguity first. Each start must equal the previous start + b. A gap ends the run; summarize each run separately. Let N be the networks in the run.
  2. Test how many can be grouped. Let n = the number of contiguous networks you try to merge: 2, 4, 8… (powers of 2 only, n ≤ N). The group spans b × n. It passes when this statement is True: 
    (start value in the octet)  mod  (block size × n)  ==  0
    Read it as: the first network’s value in the changing octet must divide evenly by the block size times the number of networks grouped. Example: starts 16, 17, 18, 19 with b = 1 and n = 4 → 16 mod (1 × 4) = 0 → True, so they merge. Starts 10–13 → 10 mod (1 × 4) = 2 → False, so n = 4 fails.
  3. Take the largest n that passes. If even n = 2 fails, advertise that network unchanged.
  4. Compute the summary. New prefix = p − log₂(n). It starts at the first network, spans b × n (its new block size), and ends at start + b × n − 1.
  5. If n < N, repeat from the first uncovered network.
  6. Verify that the summaries cover exactly the original networks and nothing more.

WHY POWERS OF 2 ONLY

A prefix shortens by whole bits, so a summary always covers 2k equal blocks. The modulo test can pass for other sizes and mislead: 48 mod (8 × 3) = 0 is true in the last example, yet three /21 blocks cannot form one prefix. The misaligned case 172.16.10 – 13 shows the cost of forcing it: one route 172.16.8.0/21 would also swallow .8, .9, .14 and .15.

Chaudhary’s two regions (Nepal and India) merge into one /13 covering 10.0.0.0 – 10.7.255.255; Pokhara’s Library, Administration and Hostels 1 and 2 merge into one /19 covering 172.16.32.0 – 172.16.63.255 (both worked in Section 6). Vianet is the classic proof of why CIDR replaced classful rules: four separate Class C routes become one /22, a prefix that does not exist among the classful /8, /16 and /24.

5.2When a Summary Spills

PROBLEM STATEMENT

Router A owns 10.1.0.0/24, .1.0/24 and .2.0/24 and advertises the whole 10.1.0.0/22. Router B, elsewhere on the WAN, owns 10.1.3.0/24 and advertises it. The /22 covers addresses A does not own. What happens to traffic for them?

  • B is up: the Core sees both routes for 10.1.3.50. The /24 is longer, so traffic goes to B. The specific route punches a hole in the summary.
  • Traffic for 10.1.1.20: only the /22 matches, so the Core sends it to A, and A’s own /24 delivers it.
  • B’s link is down: the /24 disappears, the /22 now matches 10.1.3.50, and the Core sends it to A. A has no route for it, falls back to its default route toward the Core, and the packet loops until TTL expires.
THE FIX — NULL0 DISCARD ROUTE

Any router that originates a summary also holds 10.1.0.0/22 → Null0. Many protocols add it automatically (EIGRP summary, OSPF area range); otherwise: ip route 10.1.0.0 255.255.252.0 Null0.

Router A: 10.1.0.0/24, .1.0/24, .2.0/24 connected · 10.1.0.0/22 → Null0 · 0.0.0.0/0 → Core

10.1.1.20: /24 beats /22 and /0  → delivered to LAN 2
10.1.3.50: /22 → Null0 beats /0  → dropped at once, no loop

The same longest-prefix rule keeps A’s specific /24s winning while the /22 catches only the one block A lacks.

Each follows the same path: pick a class, size the prefix with Formula 1, subnet with the method from Section 3, then supernet two or four blocks.

6.1Class A: Chaudhary Group

7VLSM: One Mask Is Not Enough

PROBLEM STATEMENT

Divide 192.168.50.0/24 among LAN A (Sales) 60 hosts, LAN B (Engineering) 25, LAN C (Guests) 10, and a router-to-router WAN link needing 2. Every case study so far used FLSM (one mask for all subnets: six /14s, ten /21s, four /27s), which works only when segments are similar in size. Here sizes differ wildly.

With FLSM the mask must fit the largest segment (60 hosts → /26), so all four subnets become /26 and consume the entire /24. VLSM instead gives each segment only the block it needs.

7.1The VLSM Method

  1. Sort segments largest first: 60, 25, 10, 2.
  2. Size each with Formula 1: 60 → 6 bits → /26; 25 → 5 → /27; 10 → 4 → /28; 2 → 2 → /30.
  3. Find block sizes (256 − mask octet): 64, 32, 16, 4.
  4. Place each block right after the previous one; every start must be a multiple of its own block size.
LAN A  starts   0 (multiple of 64 ✓)   0 + 64  =  64
LAN B  starts  64 (multiple of 32 ✓)  64 + 32  =  96
LAN C  starts  96 (multiple of 16 ✓)  96 + 16  = 112
WAN    starts 112 (multiple of  4 ✓) 112 + 4   = 116   116 < 256 → fits; .116–.255 free

COMMON MISTAKES

Starting right after the last host: LAN C starts at .96, not .97 (97 AND 240 = 96, so .97 is a host inside .96/28). Reserving the gateway: only network and broadcast are reserved; .1 is a usable host. Ignoring alignment: every network ID must be a multiple of its block size. Ending a range late: the /27 at .64 ends at broadcast .95, so its last host is .94.

9Key Takeaways

  1. Network address = host bits all 0; broadcast = host bits all 1. Hosts lie between.
  2. Prefix and mask are one boundary in two notations. Block size = 256 − mask octet.
  3. Subnetting borrows host bits: subnets = 2^borrowed, and subnets × block size = 256 in the split octet.
  4. Sizing: n = ⌈log₂(H + 2)⌉ host bits, prefix = 32 − n.
  5. /0 matches everything; /32 matches one host.
  6. Forwarding uses longest-prefix match on mask-ANDed addresses; AD then metric only choose which source supplies a prefix.
  7. Summarize only power-of-2, contiguous, aligned groups; otherwise split into smaller exact summaries.
  8. A router that originates a summary needs a Null0 discard route to prevent loops.
  9. FLSM is simple but wasteful when sizes differ; VLSM allocates largest first, on block-size boundaries, and needs a classless protocol.
