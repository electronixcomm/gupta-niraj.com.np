Lab 4: Configuring Static and Default Routes in a Multi-Router Topology

Packet Tracer · Cisco PT8200 routers and 2960-24TT switches · Problem statement with solution

1 Intro to PT/GNS32 Switch setup3 VLANs & router-on-a-stick4 Static & default routes5 RIPv26 OSPF / EIGRP7 STP, port security, EtherChannel8 PPP/HDLC, ACL, NAT

1. Scenario

A company has two sites. Each site has a switch carrying three VLANs and a router that does inter-VLAN routing (router-on-a-stick). Router0 serves the left site and Router1 serves the right site. They are joined by a direct link, and Router2 provides a second, backup path between them.

Your job is to make every LAN reach every other LAN using only static and default routes (no routing protocol). The direct link must be used normally, and the path through Router2 must take over automatically if the direct link fails.

Learning objectives

  • Build a multi-router topology and plan /30 point-to-point links.
  • Configure VLANs, trunks and subinterfaces (review of Lab 3).
  • Configure static routes, floating static routes and default routes.
  • Use administrative distance to control path preference and test failover.

Part 2Router-on-a-stick and DHCP relay

  1. On Router0 and Router1 create subinterfaces on G0/0/0 for VLANs 10, 20 and 100 with dot1Q encapsulation and the addresses from the table.
  2. Configure each subinterface to relay DHCP to the local server (Router0 → Server1, Router1 → Server0).
  3. On each server set its IP, mask and gateway, then enable the DHCP service and create one pool per LAN at its site (gateway = the router subinterface, start address, /24 mask, 50 users).
Checkpoint: Each laptop set to DHCP obtains an address from the correct pool (for example 192.168.1.10 on VLAN 10 left, 192.168.3.11 on VLAN 10 right) and can ping their gateway and the other VLAN at the same site.

Part 4Static routes with floating backups

  1. On Router0 add static routes to the right-site LANs (192.168.3.0/24 and 192.168.4.0/24) through Router1's direct link.
  2. Add backup routes to the same networks through Router2, with an administrative distance high enough that they are used only when the direct link fails.
  3. Do the same on Router1 for the left-site LANs (192.168.1.0/24 and 192.168.2.0/24).
Checkpoint: show ip route static shows only the AD 1 routes. Laptop0 pings Laptop4 and Laptop2 pings Laptop6, and the reverse.
Show solution
! Router0
ip route 192.168.3.0 255.255.255.0 10.0.12.2
ip route 192.168.4.0 255.255.255.0 10.0.12.2
ip route 192.168.3.0 255.255.255.0 10.0.12.6 100
ip route 192.168.4.0 255.255.255.0 10.0.12.6 100

! Router1
ip route 192.168.1.0 255.255.255.0 10.0.12.1
ip route 192.168.2.0 255.255.255.0 10.0.12.1
ip route 192.168.1.0 255.255.255.0 10.0.12.9 100
ip route 192.168.2.0 255.255.255.0 10.0.12.9 100

A normal static route has AD 1. The backups use AD 100, so they stay hidden in the configuration until the AD 1 route disappears (when the next hop's interface goes down).

Part 5Default routes on the transit router

  1. Router2 only forwards traffic between the other two routers. Give it default routes pointing to Router1 and Router0.
Checkpoint: show ip route on Router2 shows S* 0.0.0.0/0 via both next hops.
Show solution
! Router2
ip route 0.0.0.0 0.0.0.0 10.0.12.10
ip route 0.0.0.0 0.0.0.0 10.0.12.5
Design note: with two equal defaults, Router2 may load-balance traffic for a destination back toward the router it came from, which can loop packets during the failover in Part 6. A more precise alternative is to replace the defaults with specific routes: ip route 192.168.3.0 255.255.255.0 10.0.12.10, ip route 192.168.4.0 255.255.255.0 10.0.12.10, ip route 192.168.1.0 255.255.255.0 10.0.12.5 and ip route 192.168.2.0 255.255.255.0 10.0.12.5. Test your lab and discuss which design is safer.

Part 6Verify and test failover

  1. From each laptop, ping a laptop on the other site in a different VLAN. Run tracert from Laptop0 to Laptop4 and note the hops.
  2. Shut down Router0 G0/0/1 (the direct link) and run show ip route static on Router0.
  3. Repeat the ping and tracert, then bring the link back up with no shutdown.
Checkpoint: Normal path: 192.168.1.1 → 10.0.12.2 → destination. After the failure the AD 100 routes appear and the path goes through Router2 (hop 10.0.12.6, then 10.0.12.10). After no shutdown the direct path returns.
Show verification commands
show ip route static
show ip route
show ip interface brief
ping 192.168.3.11          ! from a left-site laptop (use the address the right laptop received)
tracert 192.168.3.11

! failover test on Router0
interface GigabitEthernet0/0/1
 shutdown
! ...test, then:
 no shutdown
