NETWORK DESIGN REFERENCE

IP Addressing: Classful vs. Classless

Background theory plus three complete worked designs — Chaudhary Group (Class A), Pokhara University (Class B), and UniGlobe College (Class C) — covering subnetting, supernetting, and broadcast address calculation.

1Background

1.1IPv4 Addressing Fundamentals

An IPv4 address is a 32-bit number, written as four 8-bit octets in dotted-decimal notation (e.g., 192.168.1.10). Every address logically splits into two parts: the network ID, identifying which network a device belongs to, and the host ID, identifying the specific device on that network. How that split happens is exactly what differs between classful and classless addressing.

1.2Classful Addressing (1981–1993)

In the original IPv4 design (RFC 791), the network/host boundary was fixed by the value of the address's leading bits. This produced five classes:

THE PROBLEM

The class boundaries are rigid. An organization needing 300 hosts couldn't get "a bit more than a Class C" — it had to be bumped to an entire Class B (65,534 addresses), wasting over 65,000 of them. Multiplied across the growing internet, this inefficiency rapidly exhausted the IPv4 address space and bloated routing tables.

1.2.1How to Select / Identify a Class

Selecting a class works two ways: reading the class off an existing address, or choosing a class when designing a network the old way.

Reading a class from an address — check the value of the first octet (or its leading bits):

Table 1a — Selecting a class from the first octet
First Octet (decimal)Leading BitsClass
1 – 1260...A
128 – 19110..B
192 – 223110.C
224 – 2391110D (multicast)
240 – 2551111E (reserved)
 
Example:  172.16.0.0
First octet = 172 → binary 10101100 → leading bits "10" → 128–191 range → Class B

Example:  200.10.0.0
First octet = 200 → binary 11001000 → leading bits "110" → 192–223 range → Class C

(127.x.x.x looks like Class A by range but is reserved for loopback — the one exception.)

Choosing a class when designing (legacy method) — count the total hosts needed and pick the smallest class that covers it, to avoid waste:

  • Up to 254 hosts → Class C is enough
  • Up to 65,534 hosts → Class B
  • Up to 16,777,214 hosts → Class A

In modern classless practice, this step is skipped entirely — Formula 1 in §1.5 (n = ⌈log₂(H+2)⌉) sizes a prefix exactly to the host count, which is the whole point of CIDR.

1.3Classless Addressing — CIDR (RFC 1519, 1993)

Classless Inter-Domain Routing (CIDR) removed the fixed class boundaries. The network/host split is instead defined by an explicit prefix length (/n), which can fall anywhere from /0 to /32, independent of the address's first octet. This enables two complementary techniques, both demonstrated below:

  • Subnetting — borrowing host bits to split one large network into several smaller ones, matching address blocks to actual site or department size.
  • Supernetting (route aggregation) — borrowing network bits to merge several contiguous smaller networks into one larger advertised block, shrinking backbone routing tables.

1.4Broadcast and Network Address Rules

For any network or subnet: the network address is the address with all host bits set to 0 — it identifies the block itself and is never assigned to a device. The broadcast address is the address with all host bits set to 1 — it is used to reach every host on that subnet at once. Usable hosts fall strictly between the two.

1.5Log Base 2 Formulas — Sizing Host Bits and Subnet Bits

Every subnetting decision comes down to how the 32 available bits are split between network/subnet bits and host bits. Because each additional bit doubles the count it controls, the exact number of bits needed is found with log base 2, rounded up to the next whole bit (a fractional bit isn't usable, so the result is always ceiling-rounded).

FORMULA 1 — HOST BITS NEEDED

To support H required hosts on a subnet, two addresses in every block are unusable (the network address and the broadcast address), so:

n = ⌈ log₂(H + 2) ⌉

Verification:  2ⁿ − 2  ≥  H
FORMULA 2 — SUBNET BITS NEEDED

To create at least N separate subnets from one block, the number of bits borrowed from the network side is:

s = ⌈ log₂(N) ⌉

Verification:  2ˢ  ≥  N

Once n (host bits) is fixed by Formula 1, the new prefix length is simply 32 − n. The bits left over between the original classful prefix and the new prefix (new prefix − original prefix) automatically become available subnet bits — this is what Formula 2 checks against, to confirm enough subnets exist for the number of sites the design needs. Both formulas are applied explicitly in each class's design below.

2Class A — Chaudhary Group (CG Corporation)

2.0Why Class A?

Applying the class-selection rule from §1.2.1 to Chaudhary Group's requirement of 250,000 hosts per region:

Required hosts per region: 250,000

Class C ceiling:  254 hosts        →  250,000 > 254        →  Class C is nowhere near enough
Class B ceiling:  65,534 hosts     →  250,000 > 65,534     →  Class B is still not enough
Class A ceiling:  16,777,214 hosts →  250,000 ≤ 16,777,214 →  Class A is the smallest class that fits

Since 250,000 clears the Class B ceiling of 65,536 addresses (65,534 usable) outright, Class B is disqualified immediately — there's no in-between option in classful addressing. Class A is therefore the only class large enough to host a single 250,000-device region, which is why 10.0.0.0/8 is the correct starting block.

PROBLEM STATEMENT

Chaudhary Group, Nepal's largest multinational conglomerate, is assigned the private Class A block 10.0.0.0/8 for its global data network. It operates six regional business hubs — Nepal, India, the Middle East, Africa, Southeast Asia, and Europe — each requiring capacity for up to 250,000 connected devices (POS systems, IoT sensors, and staff endpoints across hotels, FMCG plants, and financial branches), with room to grow. Design a subnetting scheme, compute each region's network, host range, and broadcast address, and show how two adjacent regions can be summarized for the corporate backbone.

2.1Subnetting Solution

Formula 1 — host bits:
n = ⌈ log₂(H + 2) ⌉ = ⌈ log₂(250,000 + 2) ⌉ = ⌈ log₂(250,002) ⌉ = ⌈ 17.93 ⌉ = 18 bits

Verification:  2¹⁸ − 2 = 262,142 ≥ 250,000  ✓

New prefix = 32 − n = 32 − 18 = /14  (mask 255.252.0.0)

Formula 2 — subnet bits available for 6 regions:
borrowed bits = new prefix − original prefix = 14 − 8 = 6  →  2⁶ = 64 subnets available
Required: s = ⌈ log₂(6) ⌉ = ⌈ 2.58 ⌉ = 3 bits  →  64 ≥ 8 (2³), well within capacity  ✓

Block size in the 2nd octet = 256 − 252 = 4.

2.2Supernetting Solution

Nepal HQ (10.0.0.0/14) and India (10.4.0.0/14) are contiguous and bit-aligned, so they can be summarized into a single backbone route:

10.0.0.0/14   (Nepal HQ)      10.0.0.0 – 10.3.255.255
10.4.0.0/14   (India)         10.4.0.0 – 10.7.255.255
        ↓ aggregate
10.0.0.0/13   →  mask 255.248.0.0  →  covers 10.0.0.0 – 10.7.255.255

The backbone router now carries one /13 route instead of two /14 entries, while still reaching both regions.

3Class B — Pokhara University

PROBLEM STATEMENT

Pokhara University is assigned the private Class B block 172.16.0.0/16 for its main campus network. It must allocate address space for ten blocks — the Faculty of Science & Technology, Faculty of Management, Faculty of Humanities & Social Sciences, School of Health Sciences, the Central Library, Administration, and four student hostel blocks — each needing up to 2,000 hosts. Design the subnetting scheme, calculate network and broadcast addresses, and demonstrate supernetting four adjacent blocks into one backbone route.

3.1Subnetting Solution

Formula 1 — host bits:
n = ⌈ log₂(H + 2) ⌉ = ⌈ log₂(2,000 + 2) ⌉ = ⌈ log₂(2,002) ⌉ = ⌈ 10.97 ⌉ = 11 bits

Verification:  2¹¹ − 2 = 2,046 ≥ 2,000  ✓

New prefix = 32 − n = 32 − 11 = /21  (mask 255.255.248.0)

Formula 2 — subnet bits available for 10 blocks:
borrowed bits = new prefix − original prefix = 21 − 16 = 5  →  2⁵ = 32 subnets available
Required: s = ⌈ log₂(10) ⌉ = ⌈ 3.32 ⌉ = 4 bits  →  32 ≥ 16 (2⁴), well within capacity  ✓

Block size in the 3rd octet = 256 − 248 = 8.

3.2Supernetting Solution

Central Library, Administration, Hostel Block 1, and Hostel Block 2 (172.16.32.0/21 through 172.16.56.0/21) are four contiguous /21 blocks starting at an address divisible by 32 — properly aligned for aggregation into a single /19:

172.16.32.0/21   (Central Library)
172.16.40.0/21   (Administration)
172.16.48.0/21   (Hostel Block 1)
172.16.56.0/21   (Hostel Block 2)
        ↓ aggregate
172.16.32.0/19   →  mask 255.255.224.0  →  covers 172.16.32.0 – 172.16.63.255

The campus core router now advertises one /19 route to the university's edge, instead of four separate /21 routes.

4Class C — UniGlobe College

PROBLEM STATEMENT

UniGlobe College is assigned the private Class C block 192.168.1.0/24 for its Kathmandu head office, which has four departments — Admissions, Academics, IT Support, and Finance — each needing up to 25 hosts. Separately, UniGlobe's ISP, Vianet Communications, has assigned it four contiguous public Class C blocks (200.10.0.0/24 through 200.10.3.0/24) for its four branch campuses — Kathmandu, Pokhara, Chitwan, and Butwal. Design the internal subnetting for the head office, and show how Vianet supernets the four branch blocks into one advertised route.

4.1Subnetting Solution (Head Office, 192.168.1.0/24)

Formula 1 — host bits:
n = ⌈ log₂(H + 2) ⌉ = ⌈ log₂(25 + 2) ⌉ = ⌈ log₂(27) ⌉ = ⌈ 4.75 ⌉ = 5 bits

Verification:  2⁵ − 2 = 30 ≥ 25  ✓

New prefix = 32 − n = 32 − 5 = /27  (mask 255.255.255.224)

Formula 2 — subnet bits available for 4 departments:
borrowed bits = new prefix − original prefix = 27 − 24 = 3  →  2³ = 8 subnets available
Required: s = ⌈ log₂(4) ⌉ = ⌈ 2 ⌉ = 2 bits  →  8 ≥ 4 (2²), capacity confirmed  ✓

Block size in the 4th octet = 256 − 224 = 32.

4.2Supernetting Solution — Vianet's Branch Aggregation

Vianet Communications has issued four whole Class C networks to UniGlobe's four branch campuses:

200.10.0.0/24   (Kathmandu Branch)
200.10.1.0/24   (Pokhara Branch)
200.10.2.0/24   (Chitwan Branch)
200.10.3.0/24   (Butwal Branch)
        ↓ aggregate
200.10.0.0/22   →  mask 255.255.252.0  →  covers 200.10.0.0 – 200.10.3.255
                →  network address: 200.10.0.0   →  broadcast address: 200.10.3.255

This is the textbook demonstration of why CIDR replaced classful addressing: four separate "Class C" routes collapse into a single /22 announcement on Vianet's core network — a prefix length that simply does not exist under the old classful rules, which only recognized /8, /16, and /24 boundaries.

5Classful vs. Classless — Summary

AspectClassfulClassless (CIDR)
Network/host boundaryFixed by class (/8, /16, /24)Any arbitrary prefix length (/n)
Address efficiencyPoor — fixed block sizes waste addressesHigh — blocks sized to actual need
SubnettingLimited to class-default masksFull VLSM support
SupernettingNot possibleFully supported — enables route aggregation
Routing table impactLarge — no aggregation possibleCompact, via CIDR summarization
Status todayObsolete since 1993Standard for all modern IP networking

6Key Takeaways

  1. Network address = all host bits set to 0 — identifies the block, never assigned to a device.
  2. Subnetting borrows host bits → creates smaller networks, sized to fit an actual department or campus.
  3. Supernetting borrows network bits → merges networks at aggregation points such as ISP backbones, shrinking routing tables.
  4. Broadcast address = all host bits set to 1 — always the last address in a block.
  5. Classless (CIDR) addressing is what makes both operations flexible — the reason the modern internet routes efficiently at all.
Worked examples reference Chaudhary Group, Pokhara University, UniGlobe College, and Vianet Communications for illustrative purposes only; assigned address blocks are hypothetical and not their actual production networks.
