Lab 1: Introduction to Packet Tracer and Building a Simple LAN

Packet Tracer (GNS3 notes included) · 2960-24TT switch · Problem statement with solution

1. Scenario

A small office needs a local network that connects a desktop PC, a laptop, a file server and a network printer. All devices sit on one switch and share the same subnet. As a junior network engineer, you will learn the simulator, build this LAN, assign the addresses and prove that every device can reach every other one.

Learning objectives

  • Navigate the Packet Tracer workspace: device palette, logical view, real-time and simulation modes.
  • Choose the correct devices and cables and connect them.
  • Assign static IPv4 addresses through the device GUI.
  • Test connectivity with ping and observe frames in simulation mode.
GNS3 users: GNS3 has no built-in end devices, so use VPCS (or a Docker/VM host) for the PC, laptop, server and printer, and an Ethernet switch node in place of the 2960. The addressing and tests are the same.

Part 1Explore the simulator

  1. Open Packet Tracer and identify the device palette (bottom left), the workspace and the Realtime / Simulation toggle (bottom right).
  2. Find the End Devices and Network Devices (Switches) categories and note the models you need.
  3. Switch between Logical and Physical workspace views, then return to Logical.
Checkpoint: You can name the four device categories you used and say what Realtime and Simulation modes do.
Show solution
  • Palette: bottom left. Pick a category (Network Devices, End Devices, Components, Connections), then a sub-category, then drag the device onto the workspace.
  • Realtime runs the network at normal speed. Simulation slows it down and shows each packet and its path step by step, with an Event List.
  • Logical view is the topology diagram; Physical view shows buildings, wiring closets and cabling distances.

Part 2Build the topology

  1. Place one 2960-24TT switch (Switch0), one PC, one laptop, one server and one printer.
  2. Connect each end device to the switch using a copper straight-through cable from the device's FastEthernet0 to a free switch FastEthernet port.
  3. Rename the devices exactly as in the topology (PC0, Server0, Laptop0, Printer0, Switch0).
Checkpoint: All four links show green triangles at both ends (it takes a few seconds after cabling).

Use straight-through cables because an end device is connected to a switch. A cross-over cable is for like-to-like devices (switch to switch, PC to PC). Orange link lights turn green once the switch ports finish spanning-tree start-up.

Part 3Assign static IP addresses

  1. Open each end device, go to the Config tab and select FastEthernet0.
  2. Choose Static and enter the IPv4 address and subnet mask from the table.
Checkpoint: Each device shows its correct address and mask on the Config tab, and the link stays on.
Show solution (GUI screenshots)

Config tab > FastEthernet0 > IP Configuration > Static, then fill in IPv4 Address and Subnet Mask. On PCs and laptops you can also use Desktop > IP Configuration.

The MAC and link-local IPv6 addresses in the screenshots are unique to that sample file; yours will differ. The IPv6 section is left empty in this lab.

Part 4Test connectivity

  1. On PC0 open Desktop > Command Prompt and ping Server0, Laptop0 and Printer0.
  2. Repeat from Laptop0 to PC0 and Server0.
  3. Switch to Simulation mode, send a simple ICMP ping from PC0 to Laptop0 (Add Simple PDU) and step through the Event List.
  4. On Switch0 open the CLI and look at the MAC address table.
Checkpoint: Every ping succeeds (0% loss on later attempts; the very first ping can lose one packet while ARP resolves). The switch lists four dynamic MAC addresses, one per port.

  • The first ping often shows Request timed out for one packet. The host first sends an ARP broadcast to learn the target's MAC address; later packets succeed.
  • arp -a on PC0 lists the IP-to-MAC mappings it has learned.
  • The switch learns each source MAC and the port it arrived on, so show mac address-table shows Fa0/1 to Fa0/4 with type DYNAMIC. Unknown destinations are flooded out all ports; known ones go out a single port.

Part 5Save and document

  1. Save the file as Lab1_SimpleLAN.pkt (File > Save As).
  2. Record the addressing table and the results of your pings for your lab notes.
Checkpoint: The saved file reopens with all devices, cables and IP settings intact.
