Unit 6 · Practical lab · Cisco Packet Tracer

Open Shortest Path First lab: from one area to many

This lab builds Open Shortest Path First (OSPF) routing for a company with a headquarters (HQ) site, three branch (BR) offices and a link to an Internet Service Provider (ISP). You first run everything in a single area, which is the focus of this course now. A multi-area version of the same network is included at the end for later practice.

What you will practise

  • Reading a topology and building an addressing plan from it.
  • Configuring single-area OSPF with subnet and wildcard-mask network statements.
  • Connecting a router that cannot run OSPF using static routes and redistribution.
  • Setting a stable router ID (RID), using passive interfaces and advertising a default route.
  • Verifying neighbours, routes and paths, and predicting paths from OSPF cost.
  • Finding and fixing common OSPF faults.

Time: about 3 hours for Parts 1–3. Part 4 is a separate later session.

Part 1

Problem statement

NovaTech Pvt. Ltd. has grown from one office to four. Today every router uses static routes, and each time a link fails or a new branch opens, the network team edits routes on every router by hand. Last month a fibre cut between HQ and Branch B took the branch offline for half a day, even though a second path through Branch A was available.

You have been hired as the network engineer. Your job is to replace internal static routing with OSPF so that:

  • Every internal network can reach every other internal network.
  • If a link fails, traffic automatically moves to another path without anyone touching the routers.
  • All sites can reach the Internet server at 172.31.100.10 through HQ, with only one router needing to know about the ISP.
  • No routing updates are sent toward PCs or servers, where no routers exist.
  • Each router has a predictable, easy-to-read router ID.
  • Branch C stays reachable from every site and can reach the Internet, even though its router cannot run OSPF.
Constraint: the ISP does not run OSPF with NovaTech. The link to the ISP uses static routing only, and HQ-R1 must share a default route with the rest of the company.
Constraint: the Branch C router (BR-C) is an older model that cannot run OSPF. BR-B and BR-C must use static routes between them, and no OSPF Hellos should be sent toward BR-C. BR-B must still make Branch C's network known to the rest of the OSPF network.

Task 2: Static routing at the ISP edge and to Branch C

The ISP does not run OSPF, so the edge uses static routes. The serial link is a backup, so its routes get a higher administrative distance (AD) of 10. This makes them floating static routes that appear only if the primary link fails.

HQ-R1: default route toward the ISP 
configure terminal
ip route 0.0.0.0 0.0.0.0 172.31.0.1
ip route 0.0.0.0 0.0.0.0 172.31.0.5 10
end
ISP-R: routes back to NovaTech networks 
configure terminal

Task 4: Share the default route and the Branch C network

Instead of adding a default route on every router, configure it once on HQ-R1 and let OSPF advertise it.

HQ-R1 
configure terminal
router ospf 10
 default-information originate
end

Next, OSPF must learn about 192.168.30.0/24. BR-B takes its static route and redistributes it, which means advertising a route learned another way into OSPF as an external route. Redistribution is beyond the exam objectives, but it is the standard way to connect a router that cannot run OSPF.

BR-B 
configure terminal
router ospf 10
 redistribute static subnets
end

The subnets keyword tells OSPF to redistribute subnetted routes too, not only whole classful networks. Include it by habit.

Check
  • On BR-A, show ip route includes O*E2 0.0.0.0/0 [110/1] via 10.0.1.1 and O E2 192.168.30.0/24 [110/20] via 10.0.3.2.
  • PC-C can ping the Internet-Server at 172.31.100.10 and PC-HQ at 10.1.10.10.
Why does this work without OSPF on BR-C? Outbound, PC-C → BR-C → default route → BR-B, and BR-B knows every OSPF route. Return traffic reaches BR-B because every router learned 192.168.30.0/24 from BR-B's redistribution, and BR-B's static route delivers it to BR-C.

Task 6: Cost, path selection and failover

Gigabit links cost 1 and the serial links cost 64 (108 ÷ 1,544,000). (Cost = 100 over Mbps.)

6.1 Predict first

Before running any command, calculate the total cost from HQ-R2 to PC-B's network (10.3.10.0/24) along each path:

PathYour workingTotal
HQ-R2 → BR-A → BR-BG0/2 (1) + BR-A G0/1 (1) + BR-B G0/2 (1)3
HQ-R2 → BR-B (serial)S0/0/0 (64) + BR-B G0/2 (1)65

Check with show ip route 10.3.10.0 on HQ-R2: the route should be [110/3] via 10.0.1.2.

6.2 Simulate a link failure

configure terminal
interface g0/2
 shutdown
end
show ip route 10.3.10.0

The route should switch to [110/65] via 10.0.2.2, Serial0/0/0 within a few seconds. Run a continuous ping from PC-HQ to PC-B (ping -t 10.3.10.10) while you shut the link to watch the failover. Then restore it with no shutdown.

6.3 Change the path on purpose

Management wants traffic between HQ and Branch B to use the serial link. Lower its cost on both ends:

! On HQ-R2 and on BR-B
configure terminal
interface s0/0/0
 ip ospf cost 1
end

Now the serial path costs 1 + 1 = 2, which beats 3. Confirm with show ip route 10.3.10.0, then remove the change with no ip ospf cost.

6.4 Challenge: reference bandwidth

Enter auto-cost reference-bandwidth 1000 under router ospf 10 on every OSPF router (not BR-C). Record the new cost of a Gigabit interface and of a serial interface, and explain why this command must match on all routers.

Answer
Gigabit = 1000 ÷ 1000 = 1; serial = 1000 ÷ 1.544 ≈ 647. If only some routers change the reference, they calculate costs on different scales and may choose inconsistent paths.

6.5 Optional: control the DR election

Make HQ-R2 the DR on its Ethernet links. Priority is checked first, then router ID. (Priority first, RID second, zero never.)

! HQ-R2
configure terminal
interface g0/0
 ip ospf priority 255
interface g0/2
 ip ospf priority 255
end
clear ip ospf process

Answer yes to the reset prompt, then confirm with show ip ospf interface g0/0.

Task 7: Troubleshooting

The instructor, or a partner, secretly adds one fault from the list below. Find it using only show commands, then fix it. Open a fault only after you have solved it, or if you are the one creating the fault.

Neighbour checklist: "A Stubborn Admin Hates mismatches"

Area ID, Stub flag, Authentication, Hello/Dead timers. Also check the subnet, the wildcard, and passive interfaces.

Fault 1: Nobody can reach Branch C

Break it (BR-B): router ospf 10 → no redistribute static subnets

Symptom: BR-B can ping PC-C, but no other site can. PC-C's pings leave but replies never return.

Diagnose: no O E2 192.168.30.0/24 on other routers; show ip protocols on BR-B no longer lists static redistribution.

Fix: re-enter redistribute static subnets.

Fault 2: Branch A and Branch B stop talking directly

Break it (BR-A): router ospf 10 → no network 10.0.3.0 0.0.0.3 area 0 then network 10.0.3.0 0.0.0.3 area 1

Symptom: no neighbour on the BR-A–BR-B link. The console may show a "mismatched area ID" message.

Diagnose: show ip protocols or show ip ospf interface g0/1 shows area 1 on BR-A.

Fix: put the network back into area 0.

Fault 3: PC-C reaches its gateway and nothing else

Break it (BR-C): no ip route 0.0.0.0 0.0.0.0 10.0.4.1 then ip route 0.0.0.0 0.0.0.0 10.0.4.6

Symptom: PC-C can ping 192.168.30.1 but nothing beyond BR-C.

Diagnose: show ip route on BR-C has no S* entry. The next hop 10.0.4.6 is not on any connected network, so the route is never installed.

Fix: point the default route at 10.0.4.1.

Fault 4: Branches reach each other but not the Internet

Break it (HQ-R1): router ospf 10 → no default-information originate

Symptom: internal pings work; pings to 172.31.100.10 fail from every device except Server-HQ behind HQ-R1.

Diagnose: no O*E2 route on branch routers.

Fix: re-enter default-information originate.

Fault 5: A typo in the wildcard

Break it (HQ-R2): router ospf 10 → no network 10.0.1.0 0.0.0.3 area 0 then network 10.0.1.0 0.0.0.0 area 0

Symptom: no neighbour between HQ-R2 and BR-A. The wildcard 0.0.0.0 matches only the address 10.0.1.0, which is not the interface address 10.0.1.1.

Diagnose: show ip ospf interface g0/2 returns "OSPF not enabled on GigabitEthernet0/2".

Fix: use 0.0.0.3, or 10.0.1.1 0.0.0.0.

Part 4 · for later practice

Multi-area OSPF scenario

Problem statement

NovaTech plans to open more branches. As the single-area database grows, every link flap anywhere forces every router to rerun its SPF (Shortest Path First) calculation. The team decides to split the network into three areas so that changes in one region stay there.

Area design

AreaNetworksRouters
Area 0 (backbone)10.0.0.0/30, 10.0.2.0/30 (serial), 10.1.10.0/24, 172.16.20.0/24HQ-R1, HQ-R2, BR-B
Area 110.0.1.0/30, 10.0.3.0/30, 172.16.50.0/24HQ-R2, BR-A, BR-B
Area 210.0.4.0/30 (passive), 10.3.10.0/24BR-B only
Outside OSPF192.168.30.0/24 (redistributed by BR-B as an external route)BR-C, static only
  • HQ-R2 is an ABR (areas 0 and 1).
  • BR-B is an ABR (areas 0, 1 and 2). It qualifies because its serial link to HQ-R2 is in area 0. Every ABR needs at least one interface in area 0.
  • HQ-R1 is an internal area 0 router and still the ASBR.
  • BR-B is also an ASBR because it redistributes the static route to Branch C.
  • BR-A is an internal area 1 router. BR-C still runs no OSPF; its static routes do not change.

Commands

Start from the finished single-area lab. Only the network statements change, and a network must be removed from its old area before it is added to a new one. HQ-R1 and BR-C need no changes. BR-B keeps its static route and redistribute static subnets.

end
BR-A 
configure terminal
router ospf 10

Investigate

Run tracert 10.1.10.10 from PC-C and compare it with the single-area lab.

What changed, and why?

BR-C always hands traffic to BR-B through its default route, so the question is how BR-B reaches HQ. In the single-area lab, BR-B used BR-A over Gigabit links (cost 3 to 10.1.10.0/24). In the multi-area design, BR-B is an ABR and reaches area 0 networks through the backbone. Its only backbone link is the serial link, so its cost to 10.1.10.0/24 rises to 65 and traffic now uses the slow serial link.

The lesson: area boundaries affect path selection, because routers prefer intra-area paths and ABRs use the backbone for inter-area traffic. A better design might put the BR-A links in area 0 as well. Try it, and compare the traceroute again.

Part 5

Reflection questions

1. Why did we use router-id instead of relying on interface addresses?
It gives a predictable RID that does not change if interfaces change, and it takes priority over loopback and physical addresses (Real Love Prevails). Remember to clear the process or reload if it is changed later.
2. What would happen without the passive-interface commands?
OSPF would still work, but routers would send Hellos every 10 seconds onto PC and server networks. That wastes bandwidth and lets anyone on those networks try to form a neighbour relationship with the router.
3. Why is the serial link between HQ-R2 and BR-B shown as FULL/ - instead of FULL/DR?
Serial links are point-to-point, and point-to-point networks do not elect a DR or BDR (Big Networks Pick Presidents).
4. Why is the default route marked E2 with a cost of 1 on every OSPF router?
It is an external route injected by HQ-R1. By default it is type 2 (E2), which keeps the originally advertised cost (1) and does not add internal link costs as it travels.
5. If the primary ISP link fails, what happens to Internet access?
HQ-R1's floating static route via 172.31.0.5 (AD 10) is installed, the default route still exists, so OSPF keeps advertising it. Branches notice no change. ISP-R's own floating routes send return traffic over the serial link.
6. Why must BR-B redistribute its static route? Why not add a static route for 192.168.30.0/24 on every router?
Redistribution tells every OSPF router about Branch C automatically, and removes the route if BR-B's static route disappears. Static routes on every router would have to be typed and maintained by hand, which is the problem NovaTech wanted to escape.
7. BR-C runs no OSPF. How does it survive a failure of the BR-A link?
It does not need to know. BR-C simply sends everything to BR-B. OSPF on BR-B and the other routers reroutes around the failure, and BR-C's default route stays the same.
8. Why was BR-B able to be an ABR for area 2 without a virtual link?
Its serial link to HQ-R2 is in area 0, so BR-B touches the backbone directly. An ABR must have at least one interface in area 0.
