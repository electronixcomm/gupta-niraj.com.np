Dynamic routing: link-state and hybrid protocols

Distance-vector routers trust what their neighbours tell them. Link-state routers draw their own map. This unit shows how that difference plays out in Open Shortest Path First (OSPF), how to configure and verify single-area OSPF, and where Enhanced Interior Gateway Routing Protocol (EIGRP) fits between the two worlds.

By the end of this unit you should be able to

  • Explain the characteristics of link-state routing protocols and contrast them with distance-vector protocols.
  • Describe how OSPF discovers neighbours, floods Link-State Advertisements (LSAs) and computes routes with the Shortest Path First (SPF) algorithm, also called Dijkstra's algorithm.
  • Calculate OSPF cost and wildcard masks, then configure single-area OSPF on a small network.
  • Verify OSPF with Cisco show commands and interpret their output.
  • Introduce EIGRP and compare Routing Information Protocol (RIP), OSPF and EIGRP.
6.1

Characteristics of link-state protocols

A link-state router learns the state of every link in its area, stores it in a link-state database (LSDB), and runs the Dijkstra Shortest Path First (SPF) algorithm itself. Every router in an area ends up with the same map and calculates its own best paths from it.

Distance vector (RIP)

  • Knows only distance and direction ("the network is 3 hops that way").
  • Sends the whole routing table periodically (RIP: every 30 s).
  • "Routing by rumour": trusts neighbours' tables.
  • Bellman-Ford algorithm; metric is hop count (max 15).
  • Slow convergence; prone to loops without extra fixes.

Link state (OSPF, Intermediate System to Intermediate System, IS-IS)

  • Knows the full topology of its area.
  • Sends small updates only when something changes (event-triggered).
  • Each router computes routes independently.
  • Dijkstra SPF algorithm; metric is cost (bandwidth-based).
  • Fast convergence, scalable with areas, but uses more processor (CPU) time and memory.

Key characteristics

  • Three tables: neighbour table, topology table (LSDB) and routing table.
  • Hello protocol discovers neighbours and keeps the relationship alive.
  • LSAs are flooded so all routers in the area have identical databases.
  • Triggered, partial updates instead of periodic full tables, so less bandwidth is used.
  • Hierarchical design using areas, which limits flooding and contains instability.
  • Classless: supports Variable Length Subnet Masking (VLSM), Classless Inter-Domain Routing (CIDR) and discontiguous networks.
  • Trade-off: needs more memory and CPU and is harder to design and configure.
Mnemonic: link-state routers are CHEFS

They cook their own routes from the full list of ingredients instead of eating someone else's leftovers.

  • Complete map of the area (LSDB)
  • Hierarchical design using areas
  • Event-triggered updates, not periodic
  • Fast convergence
  • SPF (Dijkstra) calculated on every router

Interior vs exterior protocols

  • IGP (Interior Gateway Protocol): routes inside one autonomous system (AS). Examples: RIP, OSPF, EIGRP, IS-IS.
  • EGP (Exterior Gateway Protocol): routes between autonomous systems. The Internet uses Border Gateway Protocol (BGP).
  • An OSPF router that connects to another routing domain or AS is an Autonomous System Boundary Router (ASBR).
6.2

OSPF fundamentals

Open Shortest Path First is an open-standard (RFC 2328, OSPFv2 for IPv4) link-state IGP. Because it is not vendor-owned, it runs on Cisco and non-Cisco routers alike, which is the main reason for its popularity.

Main features

  • Supports areas and a hierarchical design; area 0 is the backbone and every other area must connect to it.
  • Minimises update traffic with triggered, multicast updates.
  • Supports VLSM/CIDR; no auto-summarisation.
  • No hop-count limit, unlike RIP's 15.
  • Load-balances across equal-cost paths (4 by default on Cisco).
  • Administrative distance is 110.
  • OSPFv3 carries the same ideas to IPv6.

Areas and special routers

  • Backbone area (area 0): every OSPF design must have one.
  • ABR (Area Border Router): has interfaces in area 0 and in at least one other area.
  • ASBR (Autonomous System Boundary Router): connects OSPF to an external routing domain.
  • Why use areas: smaller routing tables, faster convergence, and problems stay inside one area.

Neighbour requirements

Two routers become neighbours only if these values match on the shared link:

  • Area ID
  • Stub-area flag
  • Authentication (if used)
  • Hello and Dead intervals
  • Also: same subnet and mask, and (for FULL state) the same interface MTU
Mnemonic: "A Stubborn Admin Hates mismatches"
  • Area ID
  • Stub flag
  • Authentication
  • Hello/Dead timers

How OSPF works

OSPF operation happens in three stages, in this order:

  1. Neighbour and adjacency initialisation. Hellos go out every enabled interface to multicast 224.0.0.5. Routers that agree on the parameters above become neighbours, then exchange database summaries until they are fully adjacent.
  2. LSA flooding. Link-state information is sent in Link State Update (LSU) packets to every router in the area and must be acknowledged, so all routers hold the same topology map.
  3. SPF tree calculation. Each router places itself at the root of a tree and uses Dijkstra's algorithm to find the lowest-cost path to every network in the area. The best paths go into the routing table.
Mnemonic: "Hello, Flood, Tree"

Think of a new student: first you say hello to classmates, then you get flooded with everyone's notes, then you draw your own family tree of who sits where.

Hello and Dead timers

  • Broadcast and point-to-point networks: Hello 10 s, Dead 40 s.
  • NBMA and point-to-multipoint networks: Hello 30 s, Dead 120 s.
  • Rule of thumb: Dead = 4 × Hello.

Multicast addresses

  • 224.0.0.5 (AllSPFRouters): Hellos, and updates sent by the DR to everyone.
  • 224.0.0.6 (AllDRouters): updates sent by other routers to the DR and BDR only.
Mnemonic: "Five for all, six for the chiefs"

.5 reaches every OSPF router; .6 reaches only the DR and BDR.

Who sends vs. who listens: on 224.0.0.6, every router on the segment sends its update there, but only the DR and BDR are listening — traffic only flows DROTHER → DR/BDR, never the other way. On 224.0.0.5, every router listens, including the DR itself: Hellos always go out on .5 from everyone, and the DR's own consolidated LSAs go out on .5 too. Being the main sender on an address doesn't stop a router from also being a member of that same multicast group — that's how the DR still hears its neighbours' Hellos.

OSPF packet types

Adjacencies are built with five packet types, which fit a restaurant story:

  • Hello: say hi to the waiter.
  • DBD (Database Description): read the menu, a summary of what the other side has.
  • LSR (Link-State Request): order the dishes you don't have.
  • LSU (Link-State Update): the dishes arrive, carrying the actual LSAs.
  • LSAck: say thank you, confirming receipt.

Neighbour states

Down → Init → 2-Way → ExStart → Exchange → Loading → Full. In the chapter's logs you will see messages such as from LOADING to FULL, Loading Done, meaning the adjacency has just completed.

Mnemonic: "Down In The Early Evening Lovers Fall"

Down, Init, Two-Way, ExStart, Exchange, Loading, Full.

DR/BDR election (multi-access networks only)

  • Highest interface priority wins (default 1, range 0–255).
  • If priorities tie, the highest Router ID wins.
  • Priority 0 means the router can never become DR or BDR.
  • The election is not pre-emptive: a better router joining later does not take over until the DR fails.
  • Point-to-point links have no election; show ip ospf neighbor shows FULL/ -.
Mnemonic: "Priority first, RID second, zero never"

Neighbour vs. adjacency, visualised

These two get used almost interchangeably, but OSPF treats them as distinct stages. On a multi-access segment, being a neighbour only requires matching Hello parameters — everyone gets there. Becoming adjacent means fully exchanging link-state databases, and that only happens between a router and the DR/BDR.

Trap to watch for: the neighbour/adjacency gap only exists because of the DR/BDR mechanism, and that mechanism only runs on broadcast and NBMA networks. On a point-to-point link there's just one other router to talk to — no full-mesh problem to avoid — so becoming neighbours there means becoming fully adjacent. Don't generalise the gap to every network type.

The OSPF cost metric

OSPF's metric is cost. Every outgoing interface has a cost, and a route's cost is the sum of the outgoing interface costs along the path. Cisco calculates it from bandwidth:

Cost = Reference bandwidth ÷ Interface bandwidth = 108 ÷ bandwidth (bps)

InterfaceBandwidthDefault cost
Serial (T1)1.544 Mbps64
Ethernet10 Mbps10
FastEthernet100 Mbps1
GigabitEthernet1000 Mbps1 (cost cannot go below 1)
  • Override per interface with ip ospf cost 1-65535.
  • Because 100 Mbps and 1 Gbps both cost 1, modern networks raise the reference with auto-cost reference-bandwidth (set it the same on every router).
  • Worked example: Corp's route O 192.168.20.0/24 [110/65] means AD 110 and cost 65 = 64 (serial link) + 1 (LA's FastEthernet LAN).
Mnemonic: "Cost = 100 over Mbps"

With the default reference, just divide 100 by the link speed in Mbps. Fast link, low cost; lower total cost wins.

Configuring single-area OSPF

Only two commands are needed at minimum.

Router(config)#router ospf process-id          ! 1–65535, locally significant
Router(config-router)#network address wildcard area area-id
  • Process ID (1–65,535) is local only; neighbours may use different numbers.
  • Area ID (0–4,294,967,295, or dotted form like 0.0.0.0) must match on both ends of a link.
  • The network command does two jobs: it enables OSPF on matching interfaces and advertises those networks.
Mnemonic: "Process is Private, Area must Agree"

Process IDs can differ between routers. Area IDs on a shared link cannot.

Wildcard masks

  • A 0 bit means "must match"; a 1 bit means "don't care".
  • Wildcard = 255.255.255.255 − subnet mask, which is the same as block size − 1 in the interesting octet.
  • 0.0.0.0 matches one exact interface address; this is the simplest and safest choice.
  • /30 → block 4 → wildcard 0.0.0.3; /29 → block 8 → 0.0.0.7; /28 → block 16 → 0.0.0.15; /24 → 0.0.0.255.
Mnemonic: "Wildcard is the mask flipped: block size minus one"

Try it: network-statement builder

Example: the chapter's network

Always start with show ip int brief to see exactly what the router is connected to. Three routers, three styles, same result:

! Corp — exact interface addresses (wildcard 0.0.0.0)
Corp(config)#router ospf 132
Corp(config-router)#network 10.10.10.1 0.0.0.0 area 0
Corp(config-router)#network 172.16.10.1 0.0.0.0 area 0

SF(config-router)#network 192.168.10.1 0.0.0.0 area 0

LA(config)#router ospf 100
LA(config-router)#network 192.168.20.0 0.0.0.255 area 0

Useful extras

  • passive-interface fa0/1: stop sending Hellos on an interface (for example a LAN with no routers) while still advertising its network.
  • default-information originate: on the edge router with a default route, advertise it to all OSPF routers. Other routers see it as O*E2 0.0.0.0/0.
Corp(config)#ip route 0.0.0.0 0.0.0.0 fa0/0
Corp(config)#router ospf 1
Corp(config-router)#default-information originate

Router ID and loopback interfaces

A router picks its RID once, when the OSPF process starts, using this order:

  1. The router-id command under router ospf.
  2. The highest IP address on any up loopback interface.
  3. The highest IP address on any active physical interface.
  • Loopbacks are virtual interfaces that never go down, which gives a stable RID. Use a /32 host mask to save address space.
  • Changing the RID has no effect until you reload or run clear ip ospf process.
  • Create loopbacks before enabling OSPF so the RID is right from the start.
Corp(config)#interface loopback 0
Corp(config-if)#ip address 172.31.1.1 255.255.255.255
Corp(config)#router ospf 1
Corp(config-router)#router-id 223.255.255.254
Corp#clear ip ospf process
Mnemonic: "Real Love Prevails" (R → L → P)

Router-id command beats Loopback, which beats Physical interface.

Troubleshooting checklist

  • %OSPF: OSPF not enabled on FastEthernet0/0: the interface is not matched by any network statement. Check the address and wildcard.
  • No neighbours: compare area, subnet, Hello/Dead timers and authentication with show ip ospf interface.
  • Stuck in ExStart/Exchange: check for an MTU mismatch.
  • Neighbour missing on a LAN: check for a passive-interface on that interface.
  • Unexpected path: compare interface costs, especially in multi-vendor networks where costs may be calculated differently.
6.3

Introduction to EIGRP

Enhanced Interior Gateway Routing Protocol was developed by Cisco and later published as an informational RFC (RFC 7868). It is an advanced distance-vector protocol, often called a hybrid: it shares routes with neighbours like a distance-vector protocol, but borrows link-state ideas such as Hellos, neighbour tables and triggered, partial updates.

Key features

  • DUAL (Diffusing Update Algorithm) gives loop-free paths and very fast convergence.
  • Keeps three tables: neighbour, topology and routing.
  • Hellos to multicast 224.0.0.10, every 5 s on LANs (hold time 15 s).
  • Partial, bounded, triggered updates; no periodic full tables.
  • Administrative distance: 90 internal, 170 external; routes shown as D.
  • Composite metric: by default bandwidth (slowest link) and delay (sum of delays).
  • Supports equal-cost and unequal-cost load balancing (the variance command).
  • Classless, supports VLSM and both IPv4 and IPv6; maximum hop count 255 (100 by default).
Mnemonic for EIGRP metric parts: "Big Dogs Really Like Meat"

Bandwidth, Delay, Reliability, Load, MTU. Only the first two (the "Big Dogs") are used by default.

DUAL vocabulary

  • Feasible Distance (FD): this router's best total metric to a destination.
  • Reported/Advertised Distance (RD): the neighbour's own metric to that destination.
  • Successor: the neighbour on the best path; it is placed in the routing table.
  • Feasible Successor: a pre-computed backup kept in the topology table, used instantly if the successor fails.
  • Feasibility condition: a backup qualifies only if its RD < the current FD, which guarantees no loop.
Mnemonic: "Successor is the driver, Feasible Successor is the spare tyre"

The spare is already in the boot, so there is no waiting when the tyre goes flat. That is why EIGRP converges so fast.

Basic EIGRP configuration

Router(config)#router eigrp 10            ! AS number: MUST match on neighbours
Router(config-router)#network 10.0.0.0
Router(config-router)#network 172.16.10.0 0.0.0.3
Router(config-router)#no auto-summary

! Verify
Router#show ip eigrp neighbors
Router#show ip eigrp topology
Router#show ip route eigrp
Contrast with OSPF: OSPF's process ID is local, but EIGRP's AS number is not. Two EIGRP routers with different AS numbers will never become neighbours.

Self-check quiz

Answer in your head or on paper first, then open each question to check.

1. Write the command that enables OSPF process 101 on a router.
router ospf 101
2. Which command displays details of all OSPF routing processes on a router?
show ip ospf
3. Which command shows interface-specific OSPF information such as cost and timers?
show ip ospf interface
4. Which command lists all OSPF neighbours and their state?
show ip ospf neighbor
5. Which command displays the collection of OSPF link states (the LSDB)?
show ip ospf database
6. What does Cisco use to calculate OSPF cost?
Interface bandwidth: cost = 108 ÷ bandwidth in bps (reference bandwidth 100 Mbps by default).
7. Two routers are not forming an adjacency. List the likely causes.
Mismatched area ID, Hello/Dead timers, authentication, stub flag, or subnet/mask; MTU mismatch; interface not included by a network statement; or a passive-interface configured on the link. (A Stubborn Admin Hates mismatches.)
8. What is the default administrative distance of OSPF, and of internal EIGRP?
OSPF 110; internal EIGRP 90.
9. What are the default Hello and Dead timers on an Ethernet OSPF link?
Hello 10 seconds, Dead 40 seconds.
10. Write the network statement that puts the /29 subnet containing 192.168.10.49 into area 0.
network 192.168.10.48 0.0.0.7 area 0 (block size 8, so the subnet starts at .48 and the wildcard is 7).
11. A router has loopback 172.31.1.1, a physical interface 192.168.20.1, and router-id 1.1.1.1 configured. What is its RID?
1.1.1.1. The router-id command always wins (Real Love Prevails), once the process is cleared or the router reloads.
12. Two Ethernet routers both have priority 1. Router X has RID 10.1.1.1 and Router Y has RID 172.31.1.4. Which becomes DR?
Router Y: priorities tie, so the higher RID wins.
13. Why is EIGRP called a hybrid protocol?
It advertises routes to neighbours like distance vector, but uses link-state-like features: Hellos, neighbour and topology tables, and triggered partial updates. DUAL gives it loop-free fast convergence.
14. Calculate the OSPF cost from Corp to 192.168.20.0/24 over a T1 serial link and LA's FastEthernet LAN.
64 + 1 = 65, shown in the routing table as [110/65].
15. What is a DROTHER?
A router on a multi-access segment that did not win the DR or BDR election. It still forms full neighbour relationships with every router on the segment, but becomes fully adjacent only with the DR and BDR.
16. Two DROTHERs sit on the same Ethernet segment. Are they neighbours, adjacent, both, or neither?
Neighbours only. They exchange Hellos and match on the required parameters, but since neither is the DR or BDR, they never form a full adjacency with each other. Every adjacency is a neighbour, but not every neighbour is adjacent.
17. True or false: a DROTHER sends its LSAs directly to another DROTHER on the same segment.
False. It sends to the DR and BDR on 224.0.0.6; the DR then redistributes the consolidated updates on 224.0.0.5, which every router on the segment — including the BDR — is listening to.
18. On a point-to-point serial link, where no DR/BDR election happens, can two routers be neighbours without becoming adjacent?
No. The neighbour/adjacency gap exists only because of the DR/BDR election on multi-access and NBMA networks. With just one other router on a point-to-point link, there's no full-mesh problem to avoid, so becoming neighbours there means becoming fully adjacent.
